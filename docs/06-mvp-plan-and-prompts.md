# 06 · План MVP и промпты для разработки

> Версия 0.1 · 2026-11-06
> Разработка идёт этапами. Каждый этап — законченный кусок, который можно открыть на телефоне и проверить. Для каждого этапа есть готовый промпт для Claude Code.

---

## 1. Как работаем

1. Перед стартом выполняем **этап 0** (подготовка с твоей стороны) и кладём в репозиторий `CLAUDE.md` (раздел 4).
2. Один этап = одна или несколько сессий Claude Code. Вставляешь промпт этапа как есть.
3. Каждый этап заканчивается:
   - тестами, которые проходят;
   - скриншотами ключевых экранов (телефон и ПК);
   - коммитом и обновлённым файлом `docs/progress.md` (что сделано, что осталось, решения по ходу).
4. Ты проверяешь этап на своём телефоне. Замечания — следующим сообщением в той же сессии.
5. Меняется требование — сначала правим документ (01–05), потом код.

## 4. CLAUDE.md — правила проекта для разработки

Этот текст кладём в корень репозитория файлом `CLAUDE.md` на этапе 1. Claude Code читает его в каждой сессии.

```markdown
# MyGarage — правила разработки

## Что это
PWA для менеджера небольшой автомастерской в ОАЭ. Описание — в docs/01–06. Перед любой задачей
читай документ этапа и связанные разделы docs/02 (сценарии), docs/03 (экраны), docs/04 (данные).

## Стек
React + TypeScript (strict) + Vite, Mantine, React Router, TanStack Query, React Hook Form + Zod,
i18next, Dexie, vite-plugin-pwa, @react-pdf/renderer. Бэкенд — Supabase (Postgres, RLS, Storage,
Edge Functions). Тесты — Vitest, pgTAP (supabase test db), Playwright.

## Структура
app/src/{app,features,shared,locales}, supabase/{migrations,functions,tests}, docs/.

## Жёсткие правила
- Деньги — целые филсы (`*_fils`), никаких float. VAT в базисных пунктах (500 = 5%).
  Все расчёты — через shared/lib/money и shared/lib/vat; в базе — те же формулы, общие тест-кейсы.
- Время событий ставит сервер (now()). Показ — Asia/Dubai, формат ДД/ММ/ГГГГ.
- Ни одной строки интерфейса без перевода: только ключи i18next, ru.json и en.json синхронны.
- Подписанные акты, отправленные версии оценки, решения клиента, инвойсы, оплаты, движения кассы
  не изменяются и не удаляются — это обеспечивают триггеры в базе. Исправление — новой записью.
- RLS включён на каждой таблице. Публичный доступ — только через Edge Functions по токену.
- Номера машин ОАЭ: эмират + код + номер. Телефоны — E.164 (+971…).
- Мобильная вёрстка в первую очередь (390×844), затем ПК (1440×900). Кнопки ≥ 48 px.
- CSS — логические свойства (margin-inline-start и т.п.) — готовность к арабскому (RTL).
- Изменение схемы — только новой миграцией. После миграции — перегенерировать типы.

## Определение «готово»
- typecheck, lint, unit-тесты, тесты базы проходят;
- для новых сценариев — e2e-тест Playwright;
- скриншоты изменённых экранов на телефоне и ПК проверены;
- docs/progress.md обновлён; если поведение отличается от docs/01–05 — документ поправлен.

## Команды
(заполнить на этапе 1: dev, build, test, test:db, e2e, lint, typecheck, gen:types)
```

## 5. Промпты по этапам

Общая шапка, с которой начинается каждый промпт (уже включена в тексты ниже):

### Этап 1 — Каркас

**Готово, когда:** приложение ставится на телефон как PWA, вход работает, переключатель RU/EN меняет весь интерфейс, настройки мастерской сохраняются, CI зелёный.

```
Проект MyGarage. Прочитай CLAUDE.md (если его нет — создай из docs/06, раздел 4), docs/01, docs/03 (разделы 1–2, Э01, Э23), docs/04 (разделы 1, 3.1), docs/05 целиком.

Этап 1 — каркас приложения.
Сделай:
1. Проект app/ на React + TypeScript + Vite с Mantine, React Router, TanStack Query, i18next (ru/en), vite-plugin-pwa (манифест, иконки-заглушки, кэш оболочки).
2. Подключение к Supabase (dev-проект; ключи — в .env, пример в .env.example). Supabase CLI, папка supabase/ с первой миграцией: business_settings, profiles, employees, audit_log + общий триггер журнала, RLS.
3. Вход по email/паролю, быстрый PIN на устройстве, автоблокировка.
4. Оболочка: нижнее меню на телефоне (Доска, Поиск, ＋, Деньги, Ещё), боковое на ПК; переключатель RU/EN и темы в шапке; пустые страницы-заглушки всех разделов из docs/03.
5. Экран настроек мастерской (Э23: реквизиты, TRN, логотип, VAT, правила по умолчанию) и справочник сотрудников.
6. shared/lib: money (филсы, формат AED), vat (расчёт по строке с округлением), dates (Asia/Dubai), phone (E.164, +971) — с unit-тестами.
7. Скрипт проверки синхронности ru.json/en.json. ESLint, Prettier, typecheck. GitHub Actions: lint, typecheck, unit, проверка переводов.
8. Заполни раздел «Команды» в CLAUDE.md. Создай docs/progress.md.
Не делай: бизнес-сущности кроме перечисленных.
Проверка: скриншоты входа, оболочки и настроек на 390×844 и 1440×900 в обоих языках.
```

### Этап 7 — Оплаты и инвойсы

## 7. Ориентир по срокам

Зависит от того, сколько времени в неделю уделяется разработке и проверке. Ориентир при регулярной работе: этапы 1–3 — 1–2 недели, этапы 4–5 (самые важные и сложные) — 2–3 недели, этапы 6–11 — 3–4 недели, пилот — 2 недели. Итого MVP примерно за 2–3 месяца.
