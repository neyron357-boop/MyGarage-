## С0. Ленивый путь (v0.5) — как менеджер работает каждый день

Мастерская: менеджер и два механика. Машина приехала → принял → выслушал жалобу → механик посмотрел → что нашли и как
чинить → запчасти → цена клиенту → согласие → работа → оплата → выдал. Всё это — **один экран заказа и одна главная
кнопка**; заказ сам переходит по этапам, менеджер этапы руками не двигает.

| Шаг | Что делает менеджер | Что видит на заказе |
|---|---|---|
| Приём | «＋» → номер → марка/модель (чипы) → жалоба (чипы) → **«Принять»** | «Смотрим» |
| Что нашли | **«Работа»** / **«Запчасть»**: частые строки чипами (сначала те, что шли с похожей жалобой), цена из прошлого раза | «Цена» |
| Запчасти | Запчасть можно добавить без цены («Найти») → **«Спросить запчасти»**: готовое сообщение поставщику в WhatsApp (детали + машина + VIN) → закупка → цена клиенту сама с наценкой | «?» у строки без цены |
| Цена клиенту | **«Клиенту · сумма»** — смета в WhatsApp/Telegram; или клиент рядом — **«Согласен»** | «Ждём» + сколько ждём, «Напомнить» |
| Ответ | **«Согласен»** / **«Отказ»** на всё, или тап по строке — ответ по одной | «В работе» |
| Работа | По желанию: тап по строке → «Сделано», статус запчасти «Заказано / Есть» | «В работе» |
| Готово | **«Готово · сумма»** → подтверждение → инвойс | «Оплата» |
| Оплата и выдача | **«Оплата · сумма»** → **«Выдать»** | «Закрыт» |

Что бывает, и как это делается (всё — с экрана заказа):

| Ситуация | Действие |
|---|---|
| Клиент согласен на часть | Тап по строке → «Согласен» / «Отказ» |
| Клиент отказался от всего | «…» → «Отказ»: что ждало — отказ, неотправленное удаляется; платить не за что — заказ закрывается без инвойса |
| Отказ, но диагностика платная | Строка «Diagnostics» → «Согласен» → «Отказ» на остальное → «Готово» → оплата |
| Клиент молчит | В строке «Ждём N ч» — «Напомнить» (то же сообщение ещё раз) |
| Нашли ещё проблему в работе | «Работа»/«Запчасть» → заказ снова «Цена» → «Клиенту» или «Согласен» |
| Цена изменилась после отправки | Тап по строке → «Изменить» (вернётся в черновик) → новая цена → отправить |
| Клиент передумал по согласованной строке | Тап по строке → «Убрать» |
| Запчасть клиента | В листе запчасти — «Клиента» (цена 0) |
| Запчасти нет / ждём | Статус «Найти» → «Заказано» → «Есть»; на доске у заказа значок коробки |
| Спросить несколько поставщиков | «Спросить запчасти» → плитки поставщиков (WhatsApp) или «Скопировать» |
| Скидка, округлить итог | «％» рядом с кнопками строк или «…» → «Скидка» (до и после инвойса) |
| Предоплата на запчасти | «…» → «Предоплата» |
| Отдать в долг | «…» → «В долг» (подпись и срок — на вкладке оплат) |
| Оплата частями / разными способами | «Оплата» несколько раз |
| Сообщить, что готово | Значок «отправить» у инвойса: сообщение с суммой и PDF |
| Строка без VAT, цена с VAT | Под ценой: «+ VAT 5 %» · «VAT в цене» · «Без VAT» |
| Запись на потом | В «Новом заказе» — «Записать на потом»; в день приезда — «Приехал» |
| Заказ открыт по ошибке | «…» → «Удалить» (или долгое нажатие на доске), сразу «Отменить» |
| Гарантия / претензия | На закрытом заказе: «…» → «Гарантия» |
| Фото по кругу, акт приёмки с подписью | «…» → «Фото» (по желанию) |
| Всё остальное (этап вручную, документы, журнал, инцидент, возврат денег) | «…» → «Подробно» |

Подробные сценарии С1–С21 ниже остаются в силе; экраны подробного пути открываются из «Подробно».

## С1. Запись по звонку / сообщению

1. 👤 Клиент звонит или пишет в WhatsApp. Менеджер нажимает **«+ Заказ»** и вводит номер машины или телефон.
2. 📱 Ищет в базе.
   - **Нашёл** → показывает клиента, машину, прошлые визиты, долги, отказанные рекомендации («в прошлый раз отказался от колодок»).
   - **Не нашёл** → короткая форма: имя, телефон (+971), номер машины, марка/модель. Остальное заполним при приёмке.
3. 👤 Записывает жалобу коротко и выбирает дату/время приезда (или «приедет сейчас»).
4. 📱 Создаёт заказ в этапе **Запись**. Предлагает отправить подтверждение в WhatsApp: «Ждём вас 12/11 в 10:00, адрес: …, локация: …».
5. 📱 Утром в день записи показывает на доске «сегодня приедут».

**Результат:** заказ в этапе «Запись». **Если не приехал:** отметка «не приехал», заказ в «Отменён» с причиной (статистика неявок).

## С2. Приёмка машины

Цель — за 5 минут зафиксировать состояние машины так, чтобы любой спор потом решался по фото.

1. 👤 Открывает заказ (или создаёт новый, если клиент приехал без записи) → **«Начать приёмку»**.
2. 📱 **Шаг 1. Машина и клиент.** Проверка данных. Фото Mulkiya (техпаспорта) — из него переписываем VIN, год, модель (в v2 — автоматически).
3. 📱 **Шаг 2. Фото по кругу.** Показывает силуэт ракурса и подсказку «Передний левый угол». 8 обязательных кадров: перед, зад, левый бок, правый бок, 4 угла. Дополнительно: колёса/диски, крыша, лобовое стекло. Без обязательных кадров дальше не пускает (можно пропустить с причиной: «темно», «машина грязная» — причина попадает в акт).
4. 📱 **Шаг 3. Повреждения.** Схема машины (вид сверху и с боков). 👤 Тап по месту → тип (царапина / вмятина / скол / трещина / ржавчина / другое) → фото крупно. Кнопка «Повреждений нет» — тоже фиксируется.
5. 📱 **Шаг 4. Приборная панель.** 👤 Включает зажигание и фотографирует панель. Вводит пробег (цифрами), уровень топлива (шкала: E · ¼ · ½ · ¾ · F), отмечает горящие лампы (Check Engine, ABS, Airbag, масло, аккумулятор, другие).
6. 📱 **Шаг 5. OBD.** 👤 Подключает сканер, фотографирует экран или вводит коды (P0300 и т.д.). Вариант «ошибок нет» или «пропустить» с причиной.
7. 📱 **Шаг 6. Что работает.** Список с тремя кнопками на каждый пункт (работает / не работает / не проверяли): кондиционер, стеклоподъёмники, центральный замок, магнитола/экран, фары, поворотники, стоп-сигналы, дворники, сигнализация, камера заднего вида.
8. 📱 **Шаг 7. Что в машине.** Ключей: 1/2/3. Запаска, домкрат, Mulkiya в машине — да/нет. Личные вещи — свободный текст или «нет». Фото салона по желанию.
9. 📱 **Шаг 8. Жалоба и следы ДТП.**
   - Жалоба клиента его словами (голосовой ввод клавиатуры телефона).
   - «Есть свежие следы ДТП, которые клиент хочет ремонтировать?» Если да — номер полицейского отчёта и его фото обязательны (см. С18).
10. 📱 **Шаг 9. Условия.** Подставляются значения по умолчанию из настроек, менеджер меняет при необходимости:
    - лимит без звонка: 0 / 100 / 200 / 500 AED / своя сумма;
    - старые запчасти: отдать клиенту / утилизировать;
    - тест-драйв: разрешён / запрещён;
    - бесплатная стоянка после готовности: N дней, потом X AED/день;
    - диагностика платная: X AED, засчитывается в ремонт;
    - ориентировочный срок готовности.
11. 📱 **Шаг 10. Подпись.** Показывает клиенту короткую сводку на его языке (RU/EN): фото-миниатюры, повреждения, пробег, топливо, лампы, условия. 👤 Клиент расписывается пальцем на экране телефона менеджера и вводит имя.
12. 📱 Замораживает акт: время сервера, подпись, хэш (цифровой отпечаток) фото и PDF. Редактировать больше нельзя — только добавить «дополнение к акту» с причиной.
13. 📱 Предлагает отправить клиенту в WhatsApp: «Машина принята. Акт приёмки: ‹ссылка›».
14. 📱 Переводит заказ в этап **Диагностика/Оценка**, назначает механика (👤 выбирает одного из двух).

**Результат:** 📄 Акт приёмки (PDF + страница по ссылке).
**Если интернет пропал посередине:** всё введённое и фото сохранены на телефоне; отправка продолжится автоматически.

## С3. Диагностика и первая оценка

1. 👤 Механик смотрит машину, говорит менеджеру, что нашёл.
2. 👤 Менеджер открывает **«Оценка»** в заказе. Добавляет позиции:
   - из **шаблона** («ТО 10 000 км», «Замена передних колодок»): работы и запчасти подставляются сразу;
   - вручную: работа (нормо-часы или фиксированная цена) или запчасть (название, номер, цена закупки → цена клиенту по наценке).
3. 📱 Для каждой позиции спрашивает блок:
   - **A — точно нужно** (фиксированная цена);
   - **B — может понадобиться** (вилка: мин–макс);
   - **C — рекомендуем** (с срочностью 🔴/🟡/🟢).
4. 📱 Показывает подсказки «обычно вместе с этим меняют…» → один тап добавляет в блок B.
5. 📱 Считает итог: «Точно: 450 AED. С учётом возможного: до 620 AED. Рекомендации: 300 AED». Всё с VAT 5 % (цены в интерфейсе показываются как в настройках: с VAT или без).
6. 📱 Показывает менеджеру маржу по запчастям (клиент её не видит).
7. 👤 Нажимает **«Отправить клиенту»**. Выбирает канал (WhatsApp / Telegram) — по умолчанию тот, что у клиента.
8. 📱 Создаёт **версию оценки v1** (снимок цен — больше не меняется), генерирует ссылку и сообщение на языке клиента:
   > «Здравствуйте, Ахмед! Оценка по Toyota Camry (Dubai A 12345): точно — 450 AED, возможно до 620 AED. Посмотреть и подтвердить: ‹ссылка›. Оценка действительна до 19/11.»
9. 📱 Заказ → этап **Согласование**, флажок ⏳, таймер ожидания.
10. 👤 Клиент открывает ссылку (см. «Страница клиента» в 03):
    - по каждой позиции A и C — «Согласен» / «Не надо»;
    - по позициям B — «Позвоните мне» или «Делайте, если нужно, в пределах вилки»;
    - кнопка «Подтвердить».
11. 📱 Сохраняет решения с серверным временем, IP и устройством. Уведомляет менеджера: «Ахмед согласовал 3 из 4 позиций».
12. 📱 Согласованные позиции становятся доступны механику. Отказанные из блока C уходят в «отказанные рекомендации» машины (попадут в акт выдачи и в напоминания).
13. 📱 Если нужны запчасти под заказ → этап **Ждём запчасти** (С4). Иначе → **В работе**.

**Варианты:**
- **Клиент согласовал по телефону или лично** → 👤 «Согласовано устно» по нужным позициям → 📱 записывает «устно, когда, кто принял» и готовит сообщение-подтверждение: «Как договорились по телефону: делаем … на сумму … AED». Отправка — один тап.
- **Клиент не отвечает 2 часа** → 📱 напоминает менеджеру позвонить.
- **Оценка просрочена** → 📱 ссылка показывает «Оценка устарела, свяжитесь с мастерской»; менеджер создаёт новую версию.

**Результат:** 📄 Оценка v1 (PDF + страница), согласованные позиции.

## С4. Заказ и получение запчастей

1. 📱 После согласования показывает список запчастей заказа со статусом **«нужна»**.
2. 👤 Для каждой: выбирает поставщика (из списка или новый), цену закупки, срок. В v2 — сравнивает 2–3 предложения.
3. 📱 **Правило предоплаты:** если запчасть «под заказ» и дороже порога (настройка, например 300 AED) — предлагает взять предоплату до заказа. Сообщение клиенту: «Для заказа запчасти нужна предоплата X AED». Оплата → 📄 квитанция о предоплате.
4. 👤 Нажимает **«Заказано»** → 📱 статус «заказана», ожидаемая дата; флажок заказа 📦.
5. 📱 Утром показывает список **«Забрать сегодня»** по поставщикам: что, где, сколько денег взять.
6. 👤 Забрал → **«Получено»**: фото чека поставщика, фактическая цена закупки, VAT из чека. Если цена выросла и это меняет сумму для клиента → 📱 предлагает доп. согласование (С5).
7. 📱 Если расплатился наличными из кассы — автоматически создаёт расход наличных с привязкой к заказу.
8. 📱 Когда все запчасти для согласованных работ получены → предлагает перевести заказ в **В работе**.

**Результат:** у каждой запчасти — поставщик, цена закупки, чек, статус.

## С5. Нашли новую проблему — доп. согласование

Главный сценарий против «цена выросла».

1. 👤 Механик зовёт менеджера: «Пыльник ШРУСа порван».
2. 👤 Менеджер в заказе → **«Нашли проблему»**.
3. 📱 Форма (≤ 2 минуты):
   - **фото/видео** проблемы (обязательно хотя бы одно);
   - что это — простыми словами (готовые фразы из справочника + свободный текст);
   - работы и запчасти с ценой (можно из шаблона);
   - срочность: 🔴 опасно ездить / 🟡 скоро понадобится / 🟢 можно отложить;
   - что будет, если не делать (одна строка).
4. 📱 **Проверяет лимит без звонка.** Если сумма ≤ остатка лимита:
   - кнопка «Согласовать по лимиту» → позиции одобрены, способ «лимит»;
   - клиенту всё равно уходит уведомление: «Нашли …, сделали в рамках вашего лимита, +80 AED. Фото: ‹ссылка›».
5. 📱 Если лимита нет или сумма больше → **«Отправить на согласование»**. Создаётся **версия оценки v2** (снимок), ссылка, сообщение:
   > «Ахмед, при разборке нашли порванный пыльник ШРУСа (фото по ссылке). Если не заменить — через 1–2 месяца выйдет из строя ШРУС (~900 AED). Замена: 80 AED. Подтвердить: ‹ссылка›».
6. 📱 Новые позиции **заблокированы** до ответа: механик видит «не делать, ждём клиента». Флажок ⏳ и таймер.
7. Ответ клиента:
   - **Согласен по ссылке** → позиции разблокированы, менеджер получает уведомление.
   - **Отказался** → позиции помечены «отказ клиента», попадают в акт выдачи («Клиент проинформирован о порванном пыльнике ШРУСа, от замены отказался 12/11/2026 14:32») и в отказанные рекомендации машины.
   - **Позвонил и согласился устно** → как в С3 (устно + письменное подтверждение).
8. 📱 В заказе видна лента версий: v1 450 → v2 +80 (причина, кто, когда, как согласовано).

**Если позиция из блока B подтвердилась:**
- клиент заранее выбрал «Делайте, если нужно, в пределах вилки» и фактическая цена не выше максимума → менеджер отмечает «понадобилось», клиенту уходит уведомление с фото;
- цена выше максимума или клиент выбрал «Позвоните мне» → обычное доп. согласование.

**Если запчасть подорожала:** то же доп. согласование с причиной «изменилась цена запчасти».

## С6. Ремонт, проверка, тест-драйв

1. 📱 Механик (в MVP — через менеджера, в v2 — сам) видит список согласованных работ. Несогласованные и отказанные — серым, с пометкой «не делать».
2. 👤 По ходу работ: фото снятых деталей и найденных дефектов, отметка «выполнено» по позициям. Выполненной можно отметить только согласованную позицию.
3. 👤 Все работы выполнены → этап **Проверка**. 📱 Чек-лист контроля качества (настраиваемый): нет подтёков, затянуты колёса, уровень жидкостей, нет новых ошибок OBD, ошибки сброшены, салон чистый, вещи клиента на месте.
4. 👤 **Тест-драйв** (только если разрешён в акте): 📱 просит фото одометра до и после. Пробег тест-драйва попадает в акт выдачи.
5. 📱 Если механик что-то повредил → С17.
6. 👤 Проверка пройдена → этап **Готово**.

---

## С7. Готово — уведомляем клиента

1. 📱 При переходе в **Готово** собирает итог: выполненные работы, установленные запчасти, сумма к оплате с VAT, уже внесённая предоплата, остаток.
2. 📱 Готовит сообщение:
   > «Ахмед, ваша Toyota Camry готова! Итого: 530 AED (с VAT), предоплата 200 AED, к оплате 330 AED. Мы работаем до 20:00. Подробности: ‹ссылка›».
3. 👤 Отправляет одним тапом.
4. 📱 Запускает счётчик бесплатной стоянки. За день до окончания — напоминание менеджеру и шаблон сообщения клиенту.

---

## С8. Выдача и оплата

1. 👤 Клиент приехал → **«Выдача»**.
2. 📱 **Шаг 1. Фото при выдаче** — те же 8 ракурсов. Показывает рядом «было» (приёмка) и «стало» для каждого ракурса.
3. 📱 **Шаг 2. Панель:** пробег, топливо, лампы. Сравнение с приёмкой; если пробег вырос больше, чем на тест-драйв, — предупреждение менеджеру.
4. 📱 **Шаг 3. Итог работ** на языке клиента:
   - выполнено (с номерами установленных запчастей, отметкой «запчасть клиента»);
   - отказанные рекомендации с датой отказа;
   - старые запчасти: отданы / утилизированы;
   - гарантия: работы — N месяцев / N км, запчасти — по условиям поставщика, запчасти клиента — без гарантии.
5. 📱 **Шаг 4. Оплата.** Сумма к оплате, способ: наличные / карта / перевод / смешанно.
   - Оплачено полностью → 📄 Tax Invoice (или Simplified) + квитанция.
   - **Оплата не полностью** → кнопка «Выдать в долг»: сумма долга, срок, подпись клиента. 📄 Расписка о долге. Флажок 💰.
6. 📱 **Шаг 5. Подпись клиента:** «Машину осмотрел, работы принял, претензий не имею».
7. 📱 Замораживает акт выдачи. Отправляет клиенту в WhatsApp: акт выдачи + инвойс + гарантийные условия.
8. 📱 Этап **Выдано**; если оплачено полностью — сразу **Закрыт**.
9. 📱 (v2) Через 2–3 дня — шаблон сообщения «Всё ли хорошо с машиной? Будем благодарны за отзыв: ‹ссылка Google Maps›».

**Результат:** 📄 Акт выдачи, Tax Invoice, квитанция, (расписка о долге).

---

## С9. Закрытие дня (касса)

1. 👤 Вечером → **«Касса» → «Закрыть день»**.
2. 📱 Показывает:
   - остаток на утро;
   - приход наличными (по заказам, предоплаты);
   - расход наличными (запчасти, расходы, авансы);
   - **должно быть в кассе: X AED**;
   - отдельно: оплаты картой и переводами за день (для сверки с терминалом и банком).
3. 👤 Пересчитывает наличные и вводит фактическую сумму.
4. 📱 Совпало — день закрыт. Не совпало — показывает расхождение и требует комментарий. Расхождение видно владельцу в отчёте.
5. 📱 Если сдал деньги владельцу или в банк → движение «инкассация» с суммой и подписью получателя (или фото).
6. 📱 Предлагает отправить отчёт дня владельцу (С11).

---

## С10. Расход

1. 👤 **«+ Расход»** (быстрая кнопка с любого экрана).
2. 📱 Форма: сумма, категория (из списка), способ оплаты (наличные из кассы / карта / перевод), фото чека, VAT из чека (если есть), комментарий, привязка к заказу (необязательно).
3. 📱 Проверяет **норму расходов** по категории: «Расходники: потрачено 1 650 из 2 000 AED (83 %)». При превышении — предупреждение и обязательный комментарий.
4. 📱 Если наличные — уменьшает кассу.

---

## С11. Отчёт владельцу

1. 👤 **«Отчёты»** → период: сегодня / неделя / месяц / свой.
2. 📱 Собирает:
   - машин принято / выдано / в работе;
   - выручка (с VAT и без), из неё работы и запчасти;
   - расходы по категориям и нормам;
   - валовая прибыль (выручка − себестоимость запчастей − расходы);
   - долги клиентов (кто, сколько, срок);
   - касса: остаток, расхождения;
   - VAT: начислено с продаж и уплачено в закупках за период.
3. 👤 **«Отправить владельцу»** → PDF в WhatsApp.

---

## С12. Претензия клиента / гарантийный возврат

1. 👤 Клиент звонит или приезжает: «После вас появилась царапина / стучит / горит Check Engine».
2. 👤 Находит машину по номеру → открывает прошлый заказ.
3. 📱 Режим **«Разбор претензии»** — всё по этому заказу на одном экране:
   - фото приёмки нужного ракурса рядом с фото выдачи;
   - отметки повреждений на схеме;
   - лампы и OBD-коды при приёмке;
   - согласованные и отказанные позиции с датами и способом согласования;
   - подписи клиента на приёмке и выдаче;
   - журнал сообщений.
4. 👤 Принимает решение:
   - **претензия необоснованна** → показывает клиенту доказательства (можно отправить ссылку на фото), фиксирует итог в журнале;
   - **гарантийный случай** → **«Гарантийный заказ»**: новый заказ, связанный с исходным, флажок 🔁. Работы по гарантии с ценой 0 для клиента, но с себестоимостью для мастерской (видно в отчётах).
5. 📱 Претензия и её итог сохраняются в истории машины.

---

## С13. Клиент со своими запчастями

1. 👤 При оценке добавляет запчасть с пометкой **«запчасть клиента»** (цена 0, себестоимость 0).
2. 📱 В оценке и инвойсе автоматически: «Запчасть предоставлена клиентом. Гарантия распространяется только на работу. Повторный демонтаж/монтаж при браке запчасти оплачивается клиентом».
3. 📱 Предлагает сфотографировать запчасть клиента (упаковка, номер) — защита, если она окажется бракованной или не той.

---

## С14. Брак или не та запчасть

1. 👤 Запчасть не подошла или бракованная → **«Возврат поставщику»**.
2. 📱 Статус «возврат», причина, фото. Ожидаемый возврат денег: сумма, способ (деньги / замена / кредит у поставщика).
3. 📱 Список «Ждём возврат от поставщиков» с суммами — чтобы деньги не потерялись.
4. 👤 Получил деньги/замену → закрывает возврат. Если деньги наличными — приход в кассу.
5. 📱 Если из-за этого сдвигается срок ремонта — шаблон сообщения клиенту.

---

## С15. Клиент не забирает машину

1. 📱 После этапа **Готово** считает дни. В последний бесплатный день — напоминание менеджеру и шаблон сообщения клиенту (с условиями стоянки, на которые он согласился в акте приёмки).
2. 📱 После окончания бесплатного срока — флажок 🅿️, начисление платной стоянки по дням (позиция в заказе, менеджер может отменить с причиной).
3. 📱 Список «Готово, не забирают» с днями и суммами.

---

## С16. Отказ после диагностики

1. 👤 Клиент посмотрел оценку и отказался от ремонта.
2. 👤 «Клиент отказался от ремонта» → 📱 заказ получает отметку **«ремонт не проводился»** и переходит в **Готово**. В заказе остаётся платная позиция «Диагностика» (если она была в условиях приёмки).
3. 📱 Выдача — по обычному сценарию С8 (фото, подпись, оплата диагностики, Tax Invoice). После оплаты заказ закрывается.
4. 📱 Все найденные проблемы уходят в «отказанные рекомендации» машины — пригодятся при следующем визите и для напоминаний.

---

## С17. Механик что-то повредил

1. 👤 Менеджер узнал о повреждении → **«Инцидент»** в заказе.
2. 📱 Форма: что случилось, кто, фото, оценка ущерба, решение (исправляем за свой счёт / сообщаем клиенту / компенсация).
3. 📱 Флажок ⚠️. Инцидент **виден только внутри** (менеджер, владелец), в документы клиента не попадает.
4. 📱 Стоимость исправления идёт в расходы мастерской с категорией «Инциденты» — владелец видит в отчёте.

---

## С18. Машина со следами ДТП

1. 📱 На шаге 8 приёмки: «Есть свежие следы ДТП, которые клиент хочет ремонтировать?»
2. 👤 **Да** → 📱 требует номер полицейского отчёта и его фото. Без них ремонт следов ДТП не добавляется в оценку (можно принять машину на другие работы).
3. 👤 **Нет**, но следы есть → 📱 они отмечены как повреждения на схеме, в акте: «Повреждения не являются предметом ремонта».

---

## С19. Ошибка в выданном инвойсе

1. 👤 Нашёл ошибку (сумма, реквизиты клиента, позиция) → в инвойсе **«Исправить»**.
2. 📱 Выданный инвойс не меняется. Создаётся **кредит-нота** на исходный инвойс и **новый инвойс** с правильными данными (следующий номер). Причина обязательна.
3. 📱 Оба документа отправляются клиенту; в отчётах учитывается итог.

---

## С20. Выплата зарплаты и аванса

1. 👤 **«Деньги» → «Зарплаты»** → механик → «Аванс» или «Зарплата за месяц».
2. 📱 Показывает оклад, уже выданные авансы, остаток к выплате.
3. 👤 Вводит сумму, способ (наличные / перевод). При наличных — расход из кассы.
4. 📱 Зарплаты попадают в расходы категории «Зарплаты».

---

## С21. Напоминания и возврат клиентов — v2

1. 📱 Каждое утро формирует список «Кому напомнить сегодня»:
   - подошло ТО по времени или по ожидаемому пробегу;
   - отказанные рекомендации, которым пора (🟡 через 1–3 месяца);
   - сезон (кондиционер перед летом);
   - «давно не были» (больше 6–12 месяцев).
2. 👤 Отмечает, кому написать → 📱 готовит персональное сообщение на языке клиента → отправка по одному тапу на каждого.
3. 📱 Если клиент записался → результат напоминания учитывается в статистике маркетинга.
