# 01 · MyGarage — Концепция приложения

> Версия 0.2 · 2026-11-06 · учтены ответы на открытые вопросы (ОАЭ, AED, VAT, каналы связи, устройства)
> Документ отвечает на вопрос «ЧТО мы строим и ЗАЧЕМ». Как строить — в документах 02–06.

---

## 1. Суть в двух предложениях

MyGarage — рабочий инструмент менеджера небольшой автомастерской в телефоне и на компьютере: от звонка клиента до выдачи машины, инвойса и отчёта владельцу всё лежит в одном месте, без бумажек.
Главная фишка: приложение **защищает мастерскую и менеджера** в двух самых конфликтных ситуациях: «вы обещали одну цену, а взяли другую» и «до вас этой царапины не было».

## 2. Контекст

| | |
|---|---|
| Страна | ОАЭ |
| Валюта и налог | AED (дирхам), VAT 5 %, мастерская зарегистрирована как плательщик VAT (есть TRN) |
| Мастерская | маленькая, 2 механика (один немного разбирается в электрике), зарплата фиксированная |
| Поток | 2–3 клиента в день, ~50–70 заказов в месяц |
| Пользователь | менеджер: приёмка, оценка, контроль ремонта, запчасти, деньги, связь с клиентом, отчёты, маркетинг |
| Каналы связи с клиентами | WhatsApp (основной), Telegram |
| Устройства | телефон (основное) и ПК |
| Интернет в гараже | стабильный |
| Оборудование | есть OBD-сканер |
| Бюджет на сервисы | не критичен, но выбираем выгодные решения |

**Вывод из масштаба:** большая CRM для сети автосервисов здесь не нужна. Нужен быстрый и простой инструмент для одного человека, у которого в руках всё. Каждая лишняя кнопка — минус.

## 3. Кто пользуется

| Роль | Что делает в приложении | Когда |
|---|---|---|
| **Менеджер** (основной пользователь) | всё | MVP |
| **Клиент** | ничего не устанавливает. Получает ссылку в WhatsApp/Telegram: смотрит акт приёмки, оценку, фото найденной проблемы, нажимает «Согласен / Отказываюсь» | MVP |
| **Владелец** | смотрит отчёты и кассу, только чтение | v2 (в MVP — отчёт PDF в WhatsApp) |
| **Механик** | видит свои задачи, отмечает «готово», добавляет фото найденной проблемы | v2 |

## 4. Боли, которые решаем (по важности)

1. **Цена выросла в процессе ремонта.** Клиент недоволен и спорит, мастерская теряет доверие и деньги.
2. **Клиент обвиняет мастерскую** в новых царапинах и поломках, которых «не было до ремонта».
3. **Бумажки и память.** Кто, что и когда согласовал, какие запчасти заказаны, где деньги.
4. **Запчасти.** Найти, сравнить цены, заказать, привезти, не потерять, вернуть брак.
5. **Деньги.** Касса, расходы, нормы расходов, долги, предоплаты, VAT, отчёт владельцу.
6. **Клиенты не возвращаются.** Нет напоминаний, нет базы, нет маркетинга.

## 5. Принципы продукта (по ним проверяем каждую фичу)

1. **Номер машины — вход во всё.** Ввёл номер (эмират + код + цифры) или VIN и сразу видишь клиента, историю, текущий заказ, долги.
2. **Ни одной суммы без подтверждения клиента.** Любое изменение цены создаёт новую версию оценки, и работа по ней заблокирована, пока клиент не согласовал. Приложение не даёт «забыть позвонить».
3. **Всё фиксируется доказательно.** Фото с серверным временем, подписи, история изменений. Подписанный акт нельзя отредактировать, только дополнить.
4. **Телефон в одной руке, руки могут быть грязными.** Крупные кнопки, минимум печатания, шаблоны, голосовой ввод через клавиатуру телефона, камера.
5. **Письменный след вместо устных договорённостей.** Договорились по телефону — приложение формирует сообщение «Как договорились…», и клиент получает его в WhatsApp.
6. **Ничего не теряется.** Интернет стабильный, но черновик приёмки и фото сохраняются на телефоне до успешной отправки на сервер.
7. **Два языка.** Интерфейс RU/EN переключается в один тап; у каждого клиента свой язык документов.

## 6. Центр приложения — Заказ

Всё строится вокруг одной сущности: **Заказ** (заказ-наряд) — конкретный визит конкретной машины.

### 6.1. Этапы заказа

```
Запись → Приёмка → Диагностика/Оценка → Согласование → Ждём запчасти → В работе
      → Проверка → Готово → Выдано → Закрыт
                                    ↘ Гарантийный возврат (новый заказ, связанный с исходным)
Из «Записи»: → Отменён (клиент не приехал или передумал до приёмки)
```

- **Отказ от ремонта после диагностики** — заказ получает отметку «ремонт не проводился» и проходит обычную выдачу: фото, оплата диагностики, подпись.

- **Выдано** — машина ушла от нас. **Закрыт** — выдано и оплачено полностью.
- Заказ может одновременно быть «В работе» по согласованным позициям и ждать ответа клиента по новой проблеме. Поэтому кроме этапа у заказа есть **флажки**:
  ⏳ ждём ответ клиента · 📦 ждём запчасть · 💰 долг · ⚠️ инцидент · 🔁 гарантийный · 🅿️ платная стоянка.

### 6.2. Главный экран — доска машин в мастерской

Карточки машин по этапам с флажками и таймерами. Сразу видно, что где застряло: «ждём запчасть 3-й день», «ждём ответ клиента 2 часа», «готово, клиент не забрал 4 дня».

## 7. Решение боли №1: «цена выросла»

Скрытые дефекты находятся при разборке, это неизбежно. Убрать проблему нельзя, но можно сделать так, чтобы клиент **заранее ожидал** этого и **сам принимал каждое решение**.

### 7.1. Оценка в трёх блоках вместо одной цифры

| Блок | Что это | Как показываем клиенту |
|---|---|---|
| **A. Точно нужно** | подтверждённые работы и запчасти | фиксированная цена |
| **B. Может понадобиться** | то, что часто выясняется при разборке этого узла | вилка цены. Клиент выбирает: «позвоните мне» или «делайте, если нужно, в пределах вилки» |
| **C. Рекомендуем** | не срочно, заметили при осмотре | цена + срочность (сейчас / через N км / можно ждать) |

Итог показываем диапазоном: **«от 450 до 620 AED»**, а не «450». Клиент, который заранее видел вилку, не воспринимает итог 580 как обман.

### 7.2. Подсказки «что обычно ещё вылезает»

При добавлении работы приложение подсказывает типичные сопутствующие позиции: «Замена сцепления → часто нужны: выжимной подшипник, сальник КПП». Сначала подсказки берутся из встроенного списка, потом приложение учится на твоей истории: «в 4 из 6 прошлых замен ремня ГРМ меняли и помпу». Подсказка одним тапом попадает в блок B.

### 7.3. Лимит без звонка

При приёмке клиент указывает: «Если найдёте что-то ещё, делайте без звонка до суммы X AED, выше — звоните». И подписывает. Работы в пределах лимита согласуются одним тапом, клиент всё равно получает уведомление «сделали в рамках вашего лимита».

### 7.4. Доп. согласование — отдельный документ

Механик нашёл проблему, менеджер за минуту создаёт **доп. согласование**:
- фото или видео проблемы (показать убедительнее, чем рассказать);
- описание простыми словами на языке клиента;
- цена работ и запчастей, срок;
- срочность: 🔴 опасно ездить / 🟡 скоро понадобится / 🟢 можно отложить;
- последствия отказа одной строкой.

Клиент получает ссылку в WhatsApp/Telegram, смотрит фото и нажимает **«Согласен»** или **«Отказываюсь»** по каждой позиции. Ответ сохраняется с серверным временем.

- **Пока нет ответа**, позиция заблокирована (её нельзя отметить выполненной), заказ подсвечен ⏳, идёт таймер.
- **Согласился по телефону** — фиксируем «устно, когда», и приложение сразу готовит письменное подтверждение в WhatsApp.
- **Отказался** — отказ остаётся в истории и печатается в акте выдачи: «Клиент проинформирован о …, от ремонта отказался». Это защита на случай, если узел потом сломается.

### 7.5. Версии оценки

Каждое согласование создаёт новую версию (v1, v2, v3) с причиной. В любой момент видно:

> v1: 450 AED → v2: +80 (найден порванный пыльник, согласовано по ссылке 14:32) → v3: +50 (подорожала запчасть, согласовано по телефону 16:10, подтверждение отправлено).

В инвойсе клиент видит ту же прозрачную историю.

### 7.6. Правила, которые снимают споры заранее

- **Срок действия оценки** (по умолчанию 7 дней), потому что цены на запчасти меняются.
- **Платная диагностика**, если причина неясна; засчитывается в ремонт, если клиент остаётся.
- **Предоплата за запчасти под заказ**, чтобы клиент не отказался, когда запчасть уже куплена.
- **Аналитика точности оценок**: насколько итог отличается от первой оценки по типам работ. Так учимся оценивать точнее.

## 8. Решение боли №2: «до вас этого не было»

### 8.1. Акт приёмки — пошаговый фото-осмотр

Приложение ведёт по шагам, ничего не пропустишь:

1. **Фото по кругу**: 8 обязательных ракурсов (перед, зад, бока, 4 угла) + колёса/диски, крыша, лобовое стекло. Можно добавить короткое видео-облёт.
2. **Отметка повреждений на схеме машины**: тап по месту → тип (царапина, вмятина, скол, трещина, ржавчина) → фото крупным планом.
3. **Панель приборов с включённым зажиганием**: пробег, уровень топлива, **горящие ошибки** (Check Engine и т.д.).
4. **Ошибки OBD** (сканер есть): коды до ремонта — фото экрана сканера или ввод кодов.
5. **Быстрая проверка, что работает**: стеклоподъёмники, кондиционер, магнитола, фары и поворотники, центральный замок, сигнализация. Варианты: «работает / не работает / не проверяли».
6. **Что в машине**: личные вещи, запаска, домкрат, количество ключей, Mulkiya (техпаспорт).
7. **Жалоба клиента его словами.**
8. **Следы ДТП**: если на машине есть свежие повреждения от аварии и клиент хочет их ремонтировать, нужен полицейский отчёт (в ОАЭ без него ремонт следов ДТП запрещён). Приложение спрашивает номер отчёта и фото.
9. **Условия**: лимит без звонка, вернуть ли старые запчасти, разрешение на тест-драйв, срок бесплатной стоянки.
10. **Подпись клиента пальцем на экране телефона** → ссылка на акт сразу уходит клиенту в WhatsApp.

После подписи акт и фото **заморожены**: время ставит сервер, редактировать нельзя.

### 8.2. Во время ремонта

- Фото найденных дефектов и снятых деталей (до и после).
- Фото пробега до и после тест-драйва, чтобы не было претензий «накрутили пробег».
- **Внутренний журнал инцидентов**: если механик что-то повредил (бывает), менеджер фиксирует это сразу и решает вопрос честно, а не узнаёт от клиента.

### 8.3. Акт выдачи

- Те же ракурсы, приложение показывает **«было / стало» рядом**.
- Выполненные работы, установленные запчасти (с номерами), отказанные рекомендации.
- Старые запчасти: отданы клиенту или утилизированы (по выбору при приёмке).
- Гарантия: на что, сколько км и месяцев.
- Подпись клиента: «Машину осмотрел, претензий не имею».

### 8.4. Гарантийный возврат

Клиент вернулся с претензией — открываешь заказ и за 10 секунд показываешь: фото при приёмке, ошибки, которые горели до ремонта, и его отказ от замены пыльника 12 марта.

## 9. Особенности ОАЭ, заложенные в приложение

| Тема | Как учитываем |
|---|---|
| **VAT 5 %** | ставка в настройках; каждая позиция облагается или нет; итоги с VAT в AED |
| **Tax Invoice** | обязательные реквизиты: слова «Tax Invoice», название, адрес и TRN мастерской, сквозной номер, дата, позиции, ставка и сумма VAT в AED. Для компаний с TRN — полный инвойс с их реквизитами; для частных клиентов допускается упрощённый (simplified). Выданный инвойс не редактируется — исправления только через кредит-ноту (credit note) |
| **Язык инвойса** | налоговый инвойс всегда на английском (при желании — с дублированием на русском); остальные документы на языке клиента. Требования к языку уточнить у бухгалтера |
| **Электронные инвойсы (e-invoicing)** | ОАЭ вводит обязательные e-invoices через аккредитованного провайдера (ASP); для бизнеса с оборотом до AED 50 млн по текущим данным — с 1 июля 2027 (B2B/B2G). Данные инвойса храним в структурированном виде, чтобы потом подключить провайдера без переделки |
| **Входящий VAT** | у расходов и закупок запчастей храним сумму VAT из чека поставщика — для квартальной декларации и бухгалтера |
| **Номера машин** | эмират (Dubai, Sharjah, Abu Dhabi, Ajman, RAK, UAQ, Fujairah) + код (буква/цифра) + номер |
| **Mulkiya** | фото техпаспорта при приёмке; VIN, год и модель берём оттуда |
| **Ремонт после ДТП** | без полицейского отчёта не берём в ремонт следы аварии; номер отчёта и фото сохраняются в заказе |
| **Телефоны** | формат +971, ссылки в WhatsApp из номера |
| **Время и даты** | часовой пояс Asia/Dubai, формат ДД/ММ/ГГГГ |
| **Отзывы** | Google Maps (основная площадка в ОАЭ) |
| **Арабский** | не в MVP, но интерфейс проектируем так, чтобы его можно было добавить (включая письмо справа налево) |

> Налоговые и юридические детали проверяем с бухгалтером мастерской перед запуском. Приложение облегчает учёт, но не заменяет бухгалтера.

## 10. Модули и возможности

Приоритеты: **MVP** — без этого не запускаемся; **v2** — сразу после; **Потом** — когда основное отлажено.

### 10.1. Клиенты и машины — MVP

- Клиент: имя, телефон, WhatsApp/Telegram, язык документов, частное лицо или компания (с TRN), откуда пришёл, заметки («платит с задержкой», «постоянный»).
- Машина: номер (эмират + код + цифры), VIN, марка/модель/год/двигатель, история пробега, все заказы.
- У клиента может быть несколько машин; у машины может смениться владелец.
- Поиск по номеру, телефону, имени, VIN — и по работам, деталям, жалобам в заказах (русские слова находят английские названия).
- *v2:* распознавание Mulkiya по фото → автозаполнение; расшифровка VIN.

### 10.2. Заказы — MVP

- Этапы, флажки и доска (раздел 6), назначение механика.
- Оценка в 3 блоках, версии, доп. согласования, ссылка для клиента.
- Шаблоны работ («ТО», «замена передних колодок») — оценка за 30 секунд.
- Прайс работ (нормо-часы × ставка или фиксированная цена), наценка на запчасти по умолчанию.
- Встроенный список «что обычно идёт вместе».
- *v2:* подсказки сопутствующих работ на основе твоей истории.

### 10.3. Приёмка и выдача — MVP

- Пошаговый акт с фото, схемой повреждений, OBD-кодами, подписью и PDF (раздел 8).

### 10.4. Запчасти — MVP (базово), v2 (полностью)

- Запчасти в заказе со статусом: **нужна → заказана → едет → получена → установлена** (или → возврат поставщику).
- Цена закупки, цена клиенту, маржа (маржу видят менеджер и владелец, клиент — нет), VAT из чека поставщика.
- Поставщики: контакты, WhatsApp, локация, сроки, заметки о надёжности; фото чека.
- **Запчасти клиента** отмечаются отдельно; гарантия только на работу, и это автоматически пишется в документах.
- Список «что забрать сегодня» у поставщиков.
- *v2:* сравнение цен у 2–3 поставщиков по одной позиции, история цен, возвраты и брак с отслеживанием денег от поставщика, небольшой склад расходников (масла, фильтры) с остатками.

### 10.5. Документы — MVP

Документы генерируются в PDF, с логотипом и реквизитами, и отправляются в один тап:
- акт приёмки;
- оценка и доп. согласования;
- Tax Invoice / Simplified Tax Invoice (сквозная нумерация, хранение, повторная отправка);
- кредит-нота (исправление инвойса);
- акт выдачи + гарантийные условия;
- квитанция об оплате или предоплате.

### 10.6. Деньги — MVP (базово), v2 (полностью)

- Оплаты по заказу: наличные, карта (терминал), банковский перевод; **частичные оплаты, предоплаты, долги**.
- Машина с долгом выдаётся только через явное действие «выдать в долг» + подпись клиента о сумме и сроке.
- **Касса**: каждое движение наличных с причиной; закрытие дня «должно быть X, по факту Y», расхождение фиксируется.
- **Расходы** по категориям (запчасти, расходники, аренда, коммуналка, зарплаты, инструмент, реклама, прочее) с фото чека и суммой VAT.
- **Нормы расходов**: лимит на категорию в месяц, предупреждение при приближении к лимиту.
- **Зарплаты**: фиксированный оклад механиков, авансы, выплаты по месяцам.
- **Отчёт владельцу** (MVP — PDF за день/неделю/месяц в WhatsApp): выручка, расходы, прибыль, долги, касса.
- *v2:* прибыль по каждому заказу, сводка VAT за квартал (выходной и входящий) для бухгалтера, кабинет владельца.

### 10.7. Связь с клиентом — MVP

- Шаблоны сообщений на двух языках: «машина принята», «оценка готова», «нужно согласование», «машина готова», «напоминание об оплате», «напоминание забрать машину».
- Отправка через WhatsApp или Telegram одной кнопкой (без платных API на старте).
- Журнал общения в заказе: что и когда отправлено, что ответил клиент, устные договорённости.

### 10.8. Маркетинг и возврат клиентов — v2

- **Напоминания о ТО** по пробегу и времени («масло меняли 6 месяцев назад» — в жарком климате ОАЭ интервалы короче) и по отказанным рекомендациям («в марте советовали заменить колодки — пора?»).
- Сезонные поводы: проверка кондиционера перед летом.
- Источник клиента (знакомые, Google Maps, соцсети, вывеска), чтобы видеть, какая реклама работает.
- После выдачи — просьба оставить отзыв в Google Maps.
- Список «давно не были» для повторного контакта.
- Простые акции и скидки (постоянным, за рекомендацию).

### 10.9. Механики — v2

- Режим механика на телефоне: мои машины, что делать, кнопка «нашёл проблему» (фото + описание) → сразу менеджеру.
- Учёт времени по работам: сколько реально заняло против норматива (зарплата фиксированная, поэтому это для загрузки и точности оценок, а не для расчёта денег).

### 10.10. Отчёты и аналитика — v2

- Выручка, прибыль, средний чек, загрузка механиков, топ работ.
- Точность оценок (первая оценка против итога).
- Сколько рекомендаций клиенты приняли, а от скольких отказались.
- Возвраты по гарантии.

### 10.11. Календарь и запись — v2

- Запись на время с учётом загрузки двух механиков, напоминание клиенту накануне.

### Потом

- Подключение e-invoicing через аккредитованного провайдера (до срока, установленного для мастерской).
- Арабский язык интерфейса и документов.
- Онлайн-запись для клиентов.
- Прямая интеграция с OBD-сканером.
- WhatsApp Business API (автоматическая отправка).
- Страница клиента с историей его машины.
- AI-помощник: перевод жалобы клиента, объяснение проблемы простыми словами, подсказки по оценке.

## 11. Ситуации из практики, заложенные заранее

| Ситуация | Что делает приложение |
|---|---|
| При ремонте нашли ещё проблему | Доп. согласование с фото → клиент нажимает «согласен / отказ», работа заблокирована до ответа |
| «Этой царапины не было» | Акт приёмки с фото, схемой и подписью; «было / стало» при выдаче |
| «Check Engine загорелся после вас» | Фото панели и коды OBD при приёмке |
| «Вы накрутили пробег» | Пробег на фото при приёмке, до и после тест-драйва; разрешение на тест-драйв в акте |
| «Пропал бензин / вещи из салона» | Уровень топлива и опись вещей в акте |
| Клиент отказался от рекомендации, а потом сломалось | Отказ зафиксирован с датой и напечатан в акте выдачи |
| Клиент принёс свои запчасти | Пометка «запчасть клиента», гарантия только на работу — в документах автоматически |
| Запчасть пришла не та или бракованная | Статус «возврат поставщику», отслеживание возврата денег |
| Заказали дорогую запчасть, клиент передумал | Правило предоплаты за запчасти под заказ |
| Цена запчасти выросла за время ожидания | Срок действия оценки + новая версия с согласованием |
| Договорились устно, клиент потом «не помнит» | Кнопка «устно согласовано» → письменное подтверждение в WhatsApp |
| Клиент неделями не забирает машину | Условия бесплатной стоянки в акте, счётчик дней, напоминания, платная стоянка |
| Клиент хочет забрать машину, но не платит | Долг фиксируется с подписью клиента, суммой и сроком, напоминания |
| Клиент отказался от ремонта после диагностики | Диагностика — отдельная платная позиция |
| На машине свежие следы ДТП | Без полицейского отчёта следы аварии в ремонт не берём; номер отчёта в заказе |
| Механик сам что-то повредил | Внутренний журнал инцидентов — решаем честно и заранее |
| Повторный заезд по гарантии | Связь с исходным заказом, вся история и фото под рукой |
| Ошибка в выданном инвойсе | Кредит-нота, новый инвойс; оригинал не меняется |
| Касса не сходится | Ежедневное закрытие кассы, каждое движение с причиной |
| Владелец спрашивает «как дела» | Отчёт в один тап |

## 12. Чего НЕ делаем в первой версии

- Учёт большого склада, полноценную бухгалтерию, подачу VAT-декларации (только выгрузку данных для бухгалтера).
- Несколько филиалов, сложные права доступа.
- Публикацию в App Store / Google Play: это веб-приложение, которое ставится на телефон и ПК как обычное (PWA).
- Платные интеграции (WhatsApp Business API, SMS-шлюзы): сначала бесплатные способы.
- Подключение e-invoicing — данные готовим, подключаем позже (раздел 9).

## 13. Нефункциональные требования

- **Устройства:** телефон (Android/iPhone) — основное; ПК — отчёты, касса, инвойсы, длинные списки. Подпись клиента — на телефоне менеджера.
- **Скорость работы менеджера:** приёмка машины ≤ 5 минут; оценка по шаблону ≤ 1 минуты; доп. согласование ≤ 2 минут.
- **Сохранность:** черновики и фото хранятся на телефоне до успешной загрузки; ежедневный бэкап на сервере; ежемесячная полная выгрузка.
- **Безопасность:** вход по паролю, быстрая разблокировка PIN-кодом; ссылки для клиента неугадываемые и открывают только его документ.
- **Неизменяемость:** подписанные акты, отправленные оценки, выданные инвойсы и фото не редактируются; все изменения пишутся в журнал.
- **Языки:** интерфейс RU/EN, документы для клиента RU/EN; валюта, VAT, формат дат — в настройках.

## 14. Как поймём, что приложение удалось

- Бумажных бланков в мастерской — ноль.
- У каждого заказа есть подписанный акт приёмки с фото.
- Ни одного изменения цены без зафиксированного согласия клиента.
- Претензия клиента разбирается за 1 минуту по фото и истории.
- Закрытие дня и отчёт владельцу — не больше 5 минут.
- Через полгода больше повторных клиентов благодаря напоминаниям.

## 15. Принятые решения

| Вопрос | Решение |
|---|---|
| Страна, валюта, налог | ОАЭ, AED, VAT 5 % |
| Мессенджеры | WhatsApp (основной), Telegram |
| Устройства | телефон + ПК; планшета нет |
| Интернет | стабильный → полноценный офлайн-режим не нужен, достаточно сохранения черновиков |
| Оплата механиков | фиксированная зарплата |
| OBD-сканер | есть → шаг OBD в приёмке обязательный (можно пропустить с причиной) |
| Бюджет | не критичен, выбираем выгодные решения |
| Языки | интерфейс приложения RU/EN с переключением; документы проекта на русском |
| Другие конфликтные ситуации | пока нет, дополним по ходу |
