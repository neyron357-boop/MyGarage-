# MyGarage — Концепция приложения

> Версия 0.1 · черновик для обсуждения · 2026-11-06
> Статус: **описание, не разработка.** Этот документ отвечает на вопрос «ЧТО мы строим и ЗАЧЕМ». Как строить — в следующих документах (см. раздел 15).

---

## 1. Суть в двух предложениях

MyGarage — рабочий инструмент менеджера небольшой автомастерской в телефоне: от звонка клиента до выдачи машины, инвойса и отчёта владельцу всё лежит в одном месте, без бумажек.
Главная фишка: приложение **защищает мастерскую и менеджера** в двух самых конфликтных ситуациях: «вы обещали одну цену, а взяли другую» и «до вас этой царапины не было».

---

## 2. Контекст

| | |
|---|---|
| Мастерская | маленькая, 2 механика (один немного разбирается в электрике) |
| Поток | 2–3 клиента в день, ~50–70 заказов в месяц |
| Пользователь | менеджер: приёмка, оценка, контроль ремонта, запчасти, деньги, связь с клиентом, отчёты, маркетинг |
| Языки | русский и английский, переключение в один тап; документы для клиента — на его языке |

**Вывод из масштаба:** большая CRM для сети автосервисов здесь не нужна. Нужен быстрый и простой инструмент для одного человека, у которого в руках всё. Каждая лишняя кнопка — минус.

---

## 3. Кто пользуется

| Роль | Что делает в приложении | Когда |
|---|---|---|
| **Менеджер** (основной пользователь) | всё | MVP |
| **Клиент** | ничего не устанавливает. Получает ссылку или PDF в WhatsApp/Telegram: смотрит акт приёмки, оценку, фото найденной проблемы, нажимает «Согласен / Отказываюсь» | MVP (ссылка) |
| **Механик** | видит свои задачи, отмечает «готово», добавляет фото и голосовую заметку о найденной проблеме | v2 |
| **Владелец** | смотрит отчёты и кассу, только чтение | v2 |

## 4. Боли, которые решаем (по важности)

1. **Цена выросла в процессе ремонта.** Клиент недоволен и спорит, мастерская теряет доверие и деньги.
2. **Клиент обвиняет мастерскую** в новых царапинах и поломках, которых «не было до ремонта».
3. **Бумажки и память.** Кто, что и когда согласовал, какие запчасти заказаны, где деньги.
4. **Запчасти.** Найти, сравнить цены, заказать, привезти, не потерять, вернуть брак.
5. **Деньги.** Касса, расходы, нормы расходов, долги, предоплаты, отчёт владельцу.
6. **Клиенты не возвращаются.** Нет напоминаний, нет базы, нет маркетинга.

---

## 5. Принципы продукта (по ним проверяем каждую фичу)

1. **Номер машины — вход во всё.** Ввёл номер (или VIN) и сразу видишь клиента, историю, текущий заказ, долги.
2. **Ни одной суммы без подтверждения клиента.** Любое изменение цены создаёт новую версию оценки, и работа по ней заблокирована, пока клиент не согласовал. Приложение не даёт «забыть позвонить».
3. **Всё фиксируется доказательно.** Фото и видео с датой и временем, подписи, история изменений. Подписанный акт нельзя отредактировать, только дополнить.
4. **Телефон в одной руке, руки могут быть грязными.** Крупные кнопки, минимум печатания, шаблоны, голосовой ввод, камера.
5. **Письменный след вместо устных договорённостей.** Договорились по телефону — приложение формирует сообщение «Как договорились…», и клиент получает его в мессенджер.
6. **Работает при плохом интернете.** Приёмку можно провести без сети, синхронизация потом.
7. **Два языка.** Интерфейс RU/EN переключается в один тап; у каждого клиента свой язык документов.

## 6. Центр приложения — Заказ

Всё строится вокруг одной сущности: **Заказ** (заказ-наряд) — конкретный визит конкретной машины.

### Жизненный цикл заказа

```
Запись → Приёмка → Диагностика → Оценка → Согласовано клиентом
  → Ждём запчасти → В работе ⇄ Доп. согласование
  → Контроль качества → Готово (клиент уведомлён) → Выдача → Оплачено → Закрыт
                                                                  ↘ Гарантийный возврат
                                                                    (связан с исходным заказом)
```

Особые выходы:
- **«Клиент отказался после диагностики»** — оплачивает диагностику.
- **«Клиент не забирает машину»** — после N дней начинается платная стоянка (по условиям из акта приёмки).

### Главный экран — доска машин в мастерской

Карточки машин по статусам. Сразу видно, что где застряло: «ждём запчасть 3-й день», «ждём ответ клиента 2 часа», «готово, клиент не забрал».

## 7. Решение боли №1: «цена выросла»

Скрытые дефекты находятся при разборке, это неизбежно. Убрать проблему нельзя, но можно сделать так, чтобы клиент **заранее ожидал** этого и **сам принимал каждое решение**.

### 7.1. Оценка в трёх блоках вместо одной цифры

| Блок | Что это | Как показываем клиенту |
|---|---|---|
| **A. Точно нужно** | подтверждённые работы и запчасти | фиксированная цена |
| **B. Может понадобиться** | то, что часто выясняется при разборке этого узла | вилка цены + «узнаем после разборки, без вашего согласия делать не будем» |
| **C. Рекомендуем** | не срочно, заметили при осмотре | цена + срочность (сейчас / через N км / можно ждать) |

Итог показываем диапазоном: **«от 450 до 620»**, а не «450». Клиент, который заранее видел вилку, не воспринимает итог 580 как обман.

### 7.2. Подсказки «что обычно ещё вылезает»

При добавлении работы приложение подсказывает типичные сопутствующие позиции: «Замена сцепления → часто нужны: выжимной подшипник, сальник КПП». Сначала подсказки берутся из встроенного списка, потом приложение учится на твоей истории: «в 4 из 6 прошлых замен ремня ГРМ меняли и помпу». Подсказка одним тапом попадает в блок B.

### 7.3. Лимит без звонка

При приёмке клиент указывает: «Если найдёте что-то ещё, делайте без звонка до суммы X, выше — звоните». И подписывает. Это экономит время на мелочах и защищает от споров.

### 7.4. Доп. согласование — отдельный документ

Механик нашёл проблему, менеджер за минуту создаёт **доп. согласование**:
- фото или видео проблемы (показать убедительнее, чем рассказать);
- описание простыми словами на языке клиента;
- цена работ и запчастей, срок;
- срочность: 🔴 опасно ездить / 🟡 скоро понадобится / 🟢 можно отложить;
- последствия отказа одной строкой.

Клиент получает ссылку в WhatsApp/Telegram, смотрит фото и нажимает **«Согласен»** или **«Отказываюсь»**. Ответ сохраняется с датой и временем.

- **Пока нет ответа**, позиция заблокирована, заказ подсвечен «ждём клиента», идёт таймер.
- **Согласился по телефону** — фиксируем «устно, кто, когда» и автоматически отправляем письменное подтверждение.
- **Отказался** — отказ остаётся в истории и печатается в акте выдачи: «Клиент проинформирован о …, от ремонта отказался». Это защита на случай, если узел потом сломается.

### 7.5. Версии оценки

Каждое изменение создаёт новую версию (v1, v2, v3) с причиной. В любой момент видно:

> Изначально 450 → +80 (найден порванный пыльник, согласовано 14:32 в WhatsApp) → +50 (подорожала запчасть, согласовано по телефону 16:10, подтверждение отправлено).

В инвойсе клиент видит ту же прозрачную историю.

### 7.6. Правила, которые снимают споры заранее

- **Срок действия оценки** (например, 7 дней), потому что цены на запчасти меняются.
- **Платная диагностика**, если причина неясна; засчитывается в ремонт, если клиент остаётся.
- **Предоплата за запчасти под заказ**, чтобы клиент не отказался, когда запчасть уже куплена.
- **Аналитика точности оценок**: насколько итог отличается от первой оценки по типам работ. Так учимся оценивать точнее.

## 8. Решение боли №2: «до вас этого не было»

### 8.1. Акт приёмки — пошаговый фото-осмотр

Приложение ведёт по шагам, ничего не пропустишь:

1. **Фото по кругу**: 8 обязательных ракурсов (перед, зад, бока, 4 угла) + колёса/диски, крыша, стёкла. Можно добавить видео-облёт на 30 секунд.
2. **Отметка повреждений на схеме машины**: тап по месту → тип (царапина, вмятина, скол, трещина, ржавчина) → фото крупным планом.
3. **Панель приборов с включённым зажиганием**: пробег, уровень топлива, **горящие ошибки** (Check Engine и т.д.).
4. **Быстрая проверка, что работает**: стеклоподъёмники, кондиционер, магнитола, фары и поворотники, центральный замок, сигнализация. Варианты: «работает / не работает / не проверяли».
5. **Ошибки OBD** (если есть сканер): список кодов до ремонта.
6. **Что в машине**: личные вещи, запаска, домкрат, документы, количество ключей, код магнитолы.
7. **Жалоба клиента его словами** (можно голосом).
8. **Условия**: лимит без звонка, вернуть ли старые запчасти, разрешение на тест-драйв, срок бесплатной стоянки.
9. **Подпись клиента пальцем на экране** → PDF акта сразу уходит клиенту в мессенджер.

После подписи акт и фото **заморожены**: дату и время ставит система, редактировать нельзя.

### 8.2. Во время ремонта

- Фото найденных дефектов и снятых деталей (до и после).
- Фото пробега до и после тест-драйва, чтобы не было претензий «накрутили пробег».
- **Внутренний журнал инцидентов**: если механик что-то повредил (бывает), менеджер узнаёт сразу и решает вопрос честно, а не узнаёт от клиента.

### 8.3. Акт выдачи

- Те же ракурсы, приложение показывает **«было / стало» рядом**.
- Выполненные работы, установленные запчасти (с номерами), отказанные рекомендации.
- Старые запчасти: отданы клиенту или утилизированы (по выбору при приёмке).
- Гарантия: на что, сколько км и месяцев.
- Подпись клиента: «Машину осмотрел, претензий не имею».

### 8.4. Гарантийный возврат

Клиент вернулся с претензией — открываешь заказ и за 10 секунд показываешь: фото при приёмке, ошибки, которые горели до ремонта, и его отказ от замены пыльника 12 марта.

## 9. Модули и возможности

Приоритеты: **MVP** — без этого не запускаемся; **v2** — сразу после; **Потом** — когда основное отлажено.

### 9.1. Клиенты и машины — MVP

- Клиент: имя, телефон, мессенджер, язык документов, откуда пришёл, заметки («платит с задержкой», «постоянный»).
- Машина: номер, VIN, марка/модель/год/двигатель, история пробега, все заказы.
- У клиента может быть несколько машин; у машины может смениться владелец.
- Поиск по номеру, телефону, имени, VIN.
- *v2:* автоматическая расшифровка VIN, фото техпаспорта → автозаполнение.

### 9.2. Заказы — MVP

- Статусы и доска (раздел 6), назначение механика.
- Оценка в 3 блоках, версии, доп. согласования, ссылка для клиента.
- Шаблоны работ («ТО», «замена передних колодок») — оценка за 30 секунд.
- Прайс работ (нормо-часы × ставка или фиксированная цена), наценка на запчасти по умолчанию.
- *v2:* подсказки сопутствующих работ на основе истории.

### 9.3. Приёмка и выдача — MVP

- Пошаговый акт с фото, схемой повреждений, подписью и PDF (раздел 8).

### 9.4. Запчасти — MVP (базово), v2 (полностью)

- Запчасти в заказе со статусом: **нужна → заказана → едет → получена → установлена** (или → возврат поставщику).
- Цена закупки, цена клиенту, маржа (маржу видят менеджер и владелец, клиент — нет).
- Поставщики: контакты, сроки, надёжность; фото чека.
- **Запчасти клиента** отмечаются отдельно; гарантия только на работу, и это автоматически пишется в документах.
- Список «что забрать сегодня» у поставщиков.
- *v2:* сравнение цен у 2–3 поставщиков по одной позиции, история цен, возвраты и брак с отслеживанием денег от поставщика, небольшой склад расходников (масла, фильтры) с остатками.

### 9.5. Документы — MVP

Все документы генерируются в PDF на языке клиента, с логотипом и реквизитами, и отправляются в один тап:
- акт приёмки;
- оценка (смета) и доп. согласования;
- заказ-наряд / инвойс (сквозная нумерация, хранение, повторная отправка);
- акт выдачи + гарантийные условия;
- квитанция об оплате или предоплате.

### 9.6. Деньги — MVP (базово), v2 (полностью)

- Оплаты по заказу: наличные, карта, перевод; **частичные оплаты, предоплаты, долги**.
- Машина с долгом выдаётся только через явное действие «выдать в долг» + подпись клиента о сумме и сроке.
- **Касса**: каждое движение наличных с причиной; закрытие дня «должно быть X, по факту Y», расхождение фиксируется.
- **Расходы** по категориям (запчасти, расходники, аренда, коммуналка, зарплаты, инструмент, реклама, прочее) с фото чека.
- **Нормы расходов**: лимит на категорию в месяц, предупреждение при приближении к лимиту.
- *v2:* зарплата механиков (% от работ / фикс / смешанно), прибыль по каждому заказу, отчёт владельцу в один тап (день/неделя/месяц): выручка, расходы, прибыль, средний чек, долги, касса.

### 9.7. Связь с клиентом — MVP

- Шаблоны сообщений на двух языках: «машина принята», «оценка готова», «нужно согласование», «машина готова», «напоминание об оплате».
- Отправка через WhatsApp/Telegram/SMS одной кнопкой (на старте через стандартные ссылки, без платных API).
- Журнал общения в заказе: что и когда отправлено, что ответил клиент, устные договорённости.

### 9.8. Маркетинг и возврат клиентов — v2

- **Напоминания о ТО** по пробегу и времени («масло меняли 9 месяцев назад») и по отказанным рекомендациям («в марте советовали заменить колодки — пора?»).
- Источник клиента (сарафан, карты, соцсети, вывеска), чтобы видеть, какая реклама работает.
- После выдачи — просьба оставить отзыв (ссылка на Google Maps / 2GIS / Яндекс Карты).
- Список «давно не были» для повторного контакта.
- Простые акции и скидки (постоянным, за рекомендацию).

### 9.9. Механики — v2

- Режим механика на телефоне: мои машины, что делать, кнопка «нашёл проблему» (фото + голос) → сразу менеджеру.
- Учёт времени по работам: сколько реально заняло против норматива.

### 9.10. Отчёты и аналитика — v2

- Выручка, прибыль, средний чек, загрузка механиков, топ работ.
- Точность оценок (первая оценка против итога).
- Сколько рекомендаций клиенты приняли, а от скольких отказались.
- Возвраты по гарантии.

### 9.11. Календарь и запись — v2

- Запись на время с учётом загрузки двух механиков, напоминание клиенту накануне.

### Потом

- Онлайн-запись для клиентов.
- Интеграция с OBD-сканером.
- WhatsApp Business API (автоматическая отправка).
- Страница клиента с историей его машины.
- Интеграция с каталогами запчастей поставщиков.
- Фискализация / кассовый аппарат (если требует закон страны).

## 10. Ситуации из практики, заложенные заранее

| Ситуация | Что делает приложение |
|---|---|
| При ремонте нашли ещё проблему | Доп. согласование с фото → клиент нажимает «согласен / отказ», работа заблокирована до ответа |
| «Этой царапины не было» | Акт приёмки с фото, схемой и подписью; «было / стало» при выдаче |
| «Check Engine загорелся после вас» | Фото панели и коды OBD при приёмке |
| «Вы накрутили пробег» | Пробег на фото при приёмке, до и после тест-драйва; разрешение на тест-драйв в акте |
| «Пропал бензин / вещи из салона» | Уровень топлива и опись вещей в акте |
| Клиент отказался от рекомендации, а потом сломалось | Отказ зафиксирован с датой и напечатан в акте выдачи |
| Клиент принёс свои запчасти | Пометка «запчасть клиента», гарантия только на работу — в документах автоматически |
| Запчасть пришла не та или бракованная | Статус «возврат поставщику», отслеживание возврата денег |
| Заказали дорогую запчасть, клиент передумал | Правило предоплаты за запчасти под заказ |
| Цена запчасти выросла за время ожидания | Срок действия оценки + новая версия с согласованием |
| Договорились устно, клиент потом «не помнит» | Кнопка «устно согласовано» → автоматическое письменное подтверждение в мессенджер |
| Клиент неделями не забирает машину | Условия бесплатной стоянки в акте, счётчик дней, напоминания |
| Клиент хочет забрать машину, но не платит | Долг фиксируется с подписью клиента, суммой и сроком, напоминания |
| Клиент отказался от ремонта после диагностики | Диагностика — отдельная платная позиция |
| Механик сам что-то повредил | Внутренний журнал инцидентов — решаем честно и заранее |
| Повторный заезд по гарантии | Связь с исходным заказом, вся история и фото под рукой |
| Касса не сходится | Ежедневное закрытие кассы, каждое движение с причиной |
| Владелец спрашивает «как дела» | Отчёт в один тап |

## 11. Чего НЕ делаем в первой версии

- Учёт большого склада, бухгалтерию, налоговую отчётность (только выгрузку данных для бухгалтера).
- Несколько филиалов, сложные права доступа.
- Публикацию в App Store / Google Play: на старте это веб-приложение, которое ставится на телефон как обычное (PWA). Решение предварительное, окончательно — в техническом плане.
- Платные интеграции (WhatsApp API, SMS-шлюзы): сначала бесплатные способы.

## 12. Нефункциональные требования

- **Устройства:** главное — телефон (Android/iPhone); планшет для подписи клиента; компьютер для отчётов.
- **Скорость работы менеджера:** приёмка машины ≤ 5 минут; оценка по шаблону ≤ 1 минуты; доп. согласование ≤ 2 минут.
- **Офлайн:** приёмка, фото и подпись работают без интернета.
- **Сохранность данных:** автоматический бэкап; потеря телефона не означает потерю данных.
- **Безопасность:** вход по PIN или биометрии; ссылки для клиента неугадываемые и открывают только его заказ.
- **Неизменяемость:** подписанные документы и фото не редактируются, все изменения пишутся в журнал.
- **Языки:** интерфейс RU/EN, документы для клиента RU/EN; валюта, налог (НДС), формат дат — в настройках.

## 13. Как поймём, что приложение удалось

- Бумажных бланков в мастерской — ноль.
- У каждого заказа есть подписанный акт приёмки с фото.
- Ни одного изменения цены без зафиксированного согласия клиента.
- Претензия клиента разбирается за 1 минуту по фото и истории.
- Закрытие дня и отчёт владельцу — не больше 5 минут.
- Через полгода больше повторных клиентов благодаря напоминаниям.
