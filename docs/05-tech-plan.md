# 05 · Технический план

> Версия 0.1 · 2026-11-06
> Как строим: технологии, хранение данных и фото, документы, безопасность, бэкапы, стоимость. Решения выбраны под условия из 01: телефон + ПК, стабильный интернет, ОАЭ, бюджет «выгодно».

> **Как сделано сейчас (этап A):** весь фронтенд из этого плана уже работает, но данные пока хранятся на устройстве (IndexedDB через Dexie) вместо Supabase, а неизменяемость обеспечивают хуки базы в браузере. Облачная часть (разделы 4, 8–10, 12) — следующий этап. Подробности и отличия — в [progress.md](progress.md).

## 1. Главные решения коротко

| Вопрос | Решение | Почему |
|---|---|---|
| Тип приложения | **PWA** — веб-приложение, которое ставится на телефон и ПК как обычное | один код для телефона и ПК; камера, иконка на экране, полноэкранный режим; без App Store и комиссий; обновления мгновенно |
| Фронтенд | **React + TypeScript + Vite** | самый распространённый стек, много готовых библиотек, хорошо подходит для разработки с Claude Code |
| UI-библиотека | **Mantine** | готовые мобильные компоненты, формы, даты, тёмная тема; поддержка письма справа налево (для арабского в будущем) |
| Бэкенд | **Supabase** (PostgreSQL + вход + хранилище файлов + серверные функции) | реляционная база подходит для денег и отчётов; защита на уровне строк (RLS); хранилище фото; не нужно держать свой сервер |
| Хостинг фронтенда | **Cloudflare Pages** | бесплатно, быстро в ОАЭ (у Cloudflare есть узлы в регионе) |
| PDF | **@react-pdf/renderer** в браузере, шрифт Noto Sans (латиница + кириллица) | без отдельного сервера; одинаковый вид на всех устройствах |
| Сообщения клиентам | ссылки **WhatsApp click-to-chat** и **Telegram share** с готовым текстом | бесплатно, без API и одобрений Meta |
| Языки | **i18next**, файлы `ru.json` / `en.json` | стандарт; легко добавить арабский |

Отвергнутые варианты:
- **Нативные приложения (Android/iOS)** — два кода или React Native, публикация в магазинах, а ПК всё равно нужен отдельно. Для одного менеджера избыточно.
- **Firebase** — документная база неудобна для финансов, отчётов и строгих правил.
- **Свой сервер (VPS)** — дешевле на бумаге, но обновления, безопасность и бэкапы ложатся на нас.
- **Google Таблицы / no-code** — не обеспечат неизменяемость, ссылки для клиента и удобную приёмку с фото.

## 4. Бэкенд (Supabase)

### 4.1. База данных
- Таблицы и правила — по [04-data-model.md](04-data-model.md).
- **RLS включён на всех таблицах.** Роль пользователя — из `profiles.role`.
- **Триггеры неизменяемости:** запрет UPDATE/DELETE для подписанных актов, отправленных версий, решений, инвойсов, оплат, движений кассы (таблица 4.3 в 04).
- **Журнал:** общий триггер пишет изменения в `audit_log`.
- **Серверные функции в базе (RPC)** для операций, где важна точность и атомарность:
  - `change_stage(order_id, to_stage, reason)` — проверяет условия перехода (04, раздел 4.1);
  - `send_estimate_version(order_id)` — фиксирует снимок, переводит позиции в `pending`, создаёт ссылку;
  - `approve_by_limit(order_id, item_ids)` — проверяет остаток лимита;
  - `issue_invoice(order_id, type)` — считает суммы и VAT, берёт следующий номер, сохраняет снимки реквизитов;
  - `issue_credit_note(invoice_id, reason)`;
  - `close_cash_day(date, actual_fils, comment)`.
- Расчёт сумм и VAT существует в двух местах: модуль `shared/lib/vat` (для предпросмотра в интерфейсе) и функция в базе (для документов). Общий набор тестовых примеров гарантирует, что результаты совпадают.

### 4.2. Хранилище файлов
- Приватные бакеты: `media` (фото, видео, подписи), `documents` (PDF).
- Путь: `orders/{order_id}/{owner_type}/{slot}-{uuid}.jpg`.
- Пользователи приложения могут только **добавлять** файлы; изменять и удалять — нельзя (политики хранилища).
- Показ — по временным подписанным ссылкам (живут минуты).

### 4.3. Серверные функции (Edge Functions)
- `public-view` — по токену ссылки отдаёт снимок документа и временные ссылки на фото. Проверяет срок действия и отзыв ссылки.
- `public-decide` — принимает решения клиента по позициям; записывает серверное время, IP, устройство; защищён от повторной отправки и перебора токенов (ограничение частоты запросов).
- `notify` — Web Push менеджеру («Ахмед согласовал 3 из 4»).
- `export` — полная выгрузка данных и выгрузка для бухгалтера.

### 4.4. Плановые задачи (Cron)
- Каждый час: пометить просроченные версии оценок (`expired`), пересчитать флажок стоянки.
- Каждое утро: список «сегодня» — записи, стоянка, долги с наступившим сроком; v2 — напоминания о ТО.

## 5. Фото, видео и доказательства

| Что | Как |
|---|---|
| Съёмка | на телефоне — своя камера в приложении (`getUserMedia`, задняя камера 4:3): обход по кругу, одно нажатие = один ракурс, кадр = ровно то, что видно в видоискателе (до 1920 px + превью 400 px, без повторного сжатия). Без HTTPS, без доступа к камере и на ПК — системная камера / выбор файла (`<input capture>`) |
| Сжатие | длинная сторона до 1920 px, JPEG ~80 % → ~300–500 КБ; превью 400 px |
| Время съёмки | читаем из EXIF до сжатия → `device_taken_at`; доказательное время — `uploaded_at` сервера |
| Хэш | SHA-256 считается на телефоне (Web Crypto) и сохраняется в `media.sha256` |
| Черновики | каждое фото сразу кладётся в IndexedDB и в очередь загрузки; загрузка в фоне с повторами; индикатор «загружено 7 из 11» |
| Видео | MVP: до 30 секунд и до 50 МБ, без перекодирования. v2: запись в приложении в 720p для экономии места |
| Подпись | рисуется пальцем → PNG → в хранилище, ссылка в акте |
| Неизменяемость | после подписи акта файлы нельзя удалить или заменить (политики хранилища + триггеры) |

**Объём:** ~30 фото на заказ × ~0,4 МБ × 65 заказов ≈ 0,8 ГБ в месяц ≈ 10 ГБ в год. В тариф Supabase Pro входит 100 ГБ — хватит на годы.

## 6. Документы (PDF)

- Шаблоны: акт приёмки, оценка (версия), доп. согласование, акт выдачи, Tax Invoice, Simplified Tax Invoice, кредит-нота, квитанция, расписка о долге, отчёт владельцу.
- Генерируются в браузере, загружаются в хранилище, хэш сохраняется. Повторная отправка — того же файла, а не новой генерации.
- В PDF — превью фото; полноразмерные фото доступны на странице по ссылке.
- Язык: язык клиента для актов и оценок; Tax Invoice — английский (опционально + русский).
- Реквизиты инвойса — по 01, раздел 9; финальный вид согласуем с бухгалтером мастерской до запуска.

## 7. Отправка сообщений

| Канал | Телефон | ПК |
|---|---|---|
| WhatsApp | `https://wa.me/{номер}?text={текст}` — открывается чат с клиентом и готовым текстом со ссылкой | то же, открывается WhatsApp Web / Desktop |
| Telegram | `https://t.me/share/url?url={ссылка}&text={текст}` — менеджер выбирает чат | то же |
| Файл PDF | системное меню «Поделиться» (Web Share API) — можно отправить сам файл в WhatsApp | скачать и прикрепить |

- По умолчанию отправляем **ссылку** на страницу документа (клиент видит фото и может скачать PDF) — так не нужно прикреплять файл.
- После возврата в приложение — вопрос «Отправлено?» → запись в журнал сообщений.
- **Потом:** WhatsApp Business API (автоматическая отправка, статусы «доставлено/прочитано») — платно, требует одобрения Meta; подключаем, если ручной отправки станет мало.

## 8. Безопасность и доступ

- Вход: email + пароль (Supabase Auth). Быстрая разблокировка PIN-кодом на устройстве; автоблокировка через N минут.
- Роли: `manager`, `owner` (v2), `mechanic` (v2) — права по таблице 4.4 в 04.
- Публичные ссылки: токен ≥ 32 случайных байт, срок действия, возможность отзыва, ограничение частоты запросов.
- На клиентской странице — минимум личных данных.
- Секретные ключи только на сервере (в серверных функциях); в приложении — только публичный ключ Supabase.
- Все соединения по HTTPS.
- Персональные данные клиентов (имена, телефоны, номера машин) хранятся в облаке Supabase. Регион выбираем ближайший к ОАЭ из доступных при создании проекта. Требования закона ОАЭ о персональных данных к хранению за рубежом — уточнить с владельцем; для небольшой мастерской обычно не блокер.

## 15. Риски

| Риск | Что делаем |
|---|---|
| iPhone может очистить данные PWA, если приложение долго не открывать | черновики загружаем на сервер сразу, локально храним только очередь |
| Клиент не открывает ссылку | всегда есть путь «согласовано устно» + письменное подтверждение |
| Электронная подпись на экране — не нотариальная | это доказательство (подпись + фото + серверное время + хэши + отправка клиенту). Тексты условий в актах согласуем с владельцем, при желании — с юристом |
| Требования к инвойсу (VAT) | показываем образец бухгалтеру до запуска, правим шаблон |
| Менеджер один — данные «в голове» не появятся в приложении | главные сценарии требуют не больше пары минут; пилот 2 недели параллельно с текущим способом |
