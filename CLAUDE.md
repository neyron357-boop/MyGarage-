# MyGarage — правила разработки

## Что это
PWA для менеджера небольшой автомастерской в ОАЭ (AED, VAT 5 %, интерфейс RU/EN).
Описание продукта — `docs/01`–`06`, текущее состояние — `docs/progress.md`.
Перед задачей читай связанный сценарий (`docs/02`), экран (`docs/03`) и данные (`docs/04`).

## Текущая архитектура (данные на устройстве + свой сервер мастерской, v0.40)
- Всё приложение в `app/`: React 18 + TypeScript (strict) + Vite + Mantine 7 + React Router (HashRouter).
- Данные — IndexedDB через Dexie (`app/src/db/db.ts`), реактивное чтение — `useLiveQuery`. Приложение работает со
  своими данными и без сети; синхронизация идёт в фоне.
- **Свой сервер мастерской (v0.40, решение пользователя вместо Supabase из `docs/05`)** — `server/` (Node 22, без
  зависимостей, встроенная SQLite; README там же): все данные и файлы — в одной папке на ПК мастерской (`C:\MyGarage`:
  база, фото по месяцам, PDF документов по видам и месяцам, ежедневные копии базы). Работает в Docker
  (`server/docker-compose.yml` + Tailscale Funnel) или прямо в Windows (`server/windows/install-autostart.ps1`,
  автозапуск при входе); страница на ПК — http://localhost:8788 (адрес, код подключения, устройства, «Доступ из
  интернета» — Cloudflare quick tunnel, включает только владелец).
- Синхронизация в приложении — `services/sync/` (`engine.ts`, экран — `features/settings/ServerCard.tsx`,
  «Настройки → Данные → Сервер мастерской»): каждая запись, изменённая здесь, получает метку `_t` (`db/syncHooks.ts`,
  индекс в схеме v7), удаление — надгробие `syncTombs`; отправка — изменённое после последней отправки, приём —
  изменения других устройств после курсора. Побеждает последняя запись (по приходу на сервер); запись, изменённая
  здесь и ещё не отправленная, не перезаписывается; `counters` (номера) только растут (кроме `reset` главного устройства).
  **Телефон — главный (v0.41.1, решение пользователя: «главный источник данных — iPhone; в телефон данные из других
  устройств не должны загружаться»):** при подключении два набора данных никогда не смешиваются и до выбора ничего не
  синхронизируется (`pairDevice` → `finishPairing`); телефон с данными делает их данными мастерской (`makeMain` →
  `/api/sync/replace`: на сервере и других устройствах уходит всё, чего у него нет), ПК с данными при данных на сервере
  только берёт их; главное — одно (`mainDevice` сервера), заменять может только оно; после подключения — в обе стороны.
  Туннель Cloudflare живёт отдельно от сервера: перезапуск сервера (`server/windows/restart.ps1`) адрес не меняет.
  Адрес туннеля сервер читает из вывода cloudflared, когда бы тот его ни написал (v0.59.4: после перезагрузки ПК — через
  85 с; предел в минуту оставил iPhone без сервера на 8 часов) — предел ожидания не возвращать.
  Туннель — один (v0.62.3: проверка `tasklist` за 5 с говорила «не работает» о работающем — за вечер 24 cloudflared сразу,
  адрес в `server.log` прыгал каждую минуту): «остановился» — только когда и список процессов его не видит (`tunnelsOf`:
  cloudflared этой программы по её пути); прежде чем оставить или запустить туннель, остальные cloudflared этой программы
  останавливаются; адрес быстрого туннеля — только из его вывода, не из запросов (`ownTunnel` в `server/src/main.mjs`).
  **Моментально (v0.41.2, просьба пользователя):** своё изменение уходит через 0,12 с (`onLocalChange` → `scheduleSync(120)`);
  каждое устройство держит поток `GET /api/sync/events` (server-sent events, `server/src/events.mjs`) и забирает чужое в
  момент события (`listen`, «На связи» в карточке); поток переоткрывается сам (возврат в приложение, сеть, тишина > 45 с),
  проверка каждые 20 с без него и раз в минуту с ним — страховка.
  **Быстрый туннель Cloudflare потока не передаёт (v0.88**, «отправленное висит с часиками»; документация Cloudflare:
  «Quick Tunnels do not support Server-Sent Events», замер 25/11: через туннель 0 из 5 событий за 70 с, напрямую — все):
  телефон не слышал ничего живого. Теперь устройство на адресе `…trycloudflare.com` (и на любом, где поток за 4 с не дал
  первого события — `askOnly`) **спрашивает**: `GET /api/sync/poll?after=N&boot=…` — сервер держит сказанное 5 минут с
  номерами (`events.mjs` `poll`/`keep`) и отвечает в момент события (пачкой за 40 мс), иначе через 25 с пустым; ответ с
  `gap` (сервер перезапущен, ушло больше, чем держится) — устройство перечитывает своё (`tellBack`). Сервер без `poll`
  (404) — прежний поток. Не возвращать «туннель передаёт поток»; проверка — временное устройство: поток напрямую и через
  туннель одновременно (через туннель — ничего), спрашивание через туннель (те же события, на 0,2–0,6 с позже). Записи и файлы — разные очереди (`syncRecords` / `syncFiles`): фото не задерживает заказ; запись фото
  уходит, только когда её файлы на сервере (`held`) — на другом устройстве фото сразу с картинкой. Запись, пришедшая с
  сервера и не изменённая здесь (`_t === 0`), при первой отправке идёт копией (`c: 1`): не возвращает удалённое и не
  перекрывает новое. Своя установка приложения — `installId` (не стирается при «Отключить»): то же приложение, подключённое
  снова, — то же устройство (главное остаётся главным, данные сводятся). Старое приложение (без `X-Sync: 2`) сервер не
  подключает и не принимает от него записи — «Обновите приложение».
  **Связь — без сообщений (v0.42.1, «пишет нет связи с сервером — чтобы не было никогда»):** приложение говорит только о
  том, что человек исправляет сам (`lastingError`: отключено на сервере, «Обновите приложение», главное — другое); нет
  сети или сервер перезапускается — тихо пробует снова (≤ 30 с, поток — каждые 5 с), в карточке — время последней
  синхронизации. Сервер не падает от оборванной передачи файла (`pour`), неожиданное пишет в `server.log`; в Windows его
  сторожит запуск (`MyGarage Server.vbs` перезапускает через 2 с; `restart.ps1` только останавливает сервер).
  **Новый адрес — сам (v0.42.2, «чтобы iPhone сам находил новый адрес после перезагрузки ПК»):** сервер оставляет свой
  адрес на ntfy.sh для каждого подключённого устройства — тема и ключ AES-256-GCM из отпечатка его ключа
  (`server/src/relay.mjs`; в приложении то же — `services/sync/relay.ts`); не достучавшись, приложение читает свой канал и
  переходит на новый адрес, только если ключ устройства там работает (`findServer`). Не ослаблять: адрес — только
  открытый своим ключом, переход — только после `/api/status` с ключом устройства; на ntfy — только шифр.
  **ПК с сервером — файлы напрямую (v0.42.3, «на десктопной версии фото и видео открываются очень медленно»):** на
  компьютере, где работает сервер, фото и видео берутся с `http://127.0.0.1:8787` (`findNearServer`/`filesBase`, только
  если ключ устройства там работает; Chrome один раз спрашивает доступ к локальной сети — без него туннель); файлы с
  сервера — по адресу с ключом и из кеша браузера (`cachedFile`), копия «Поделиться» — после показа.
  **Фото и видео с сервера (v0.41.3, «загружаются очень медленно, сначала чёрный фон, потом резко»):** у фото на сервере
  три файла — превью (400), карточка (`card`, 1080 — доска, обложка, просмотр, «Поделиться») и оригинал; карточку
  отправляет устройство вместе с фото (`cardOf` в `services/photoSize.ts`), для старых фото её делает ПК мастерской
  средствами Windows (`server/src/cards.mjs`, System.Drawing через PowerShell); запись фото уходит, как только превью и
  карточка на сервере (`ready`), оригинал — следом. Видео и оригинал элемент грузит сам по адресу сервера
  (`mediaSrc`: ключ только для файлов `?d=&k=`, сервер отдаёт частями — Range): видео играет по мере прихода. Показ —
  `MediaImage`: превью сразу, чёткое проявляется поверх (`.media-reveal`/`.media-pic`), превью под ним затем уходит; фото, пришедшие с других
  устройств, приносятся заранее (`onMediaArrived` → превью, у фото машины — и карточка). Новое место с фото — через
  `MediaImage`/`cardUrl`/`mediaSrc`, не `mediaUrl(id, false)` (тянет оригинал целиком). Адрес с сервера ставится поверх
  того, что уже видно, только загрузившимся (v0.59.4, «Задрал… ошибки при открытии фото»: сервер недоступен — `PhotoViewer`
  рисовал «?» поверх карточки из телефона; `loads`), адрес файла на сервере не запоминается (`cachedMediaSrc` делает его
  заново — адрес сервера меняется). Изменения с сервера пишутся
  транзакцией, помеченной `markRemote`: без меток и надгробий, хуки `guard` их пропускают. Фото и PDF после
  отправки уходят с телефона (`mediaBlobs.blob` удаляется, остаются `thumb`/`card`; подписи и файлы < 48 КБ
  остаются) — читать файлы только через `services/media.ts` (`mediaUrl`, `cardUrl`, `mediaBlob`, `mediaDataUrl`): они
  приносят оригинал с сервера (`remoteMedia`). Ключ устройства и курсор — в localStorage (`services/sync/config.ts`),
  не в данных. Новые таблицы синхронизируются сами (все, кроме `LOCAL_TABLES`); новую таблицу — с индексом `_t`.
  Запись с сервера кладётся под ключ самого изменения (`applyChanges`, v0.45.1): у записи без `id` в данных (так писала
  перенумерация v0.42.3) — тоже; сервер пишет записи целиком, с `id`.
  Устройство помнит таблицы, которые принимало (`SyncState.tables`, v0.43): таблицу, добавленную обновлением, оно один раз
  догружает с начала (`catchUp` в `engine.ts`) — прежняя версия её записи пропускала, а курсор уходил дальше.
  Один раз каждое устройство дополняет недостающее (`fillHoles`, `SyncState.holes`, v0.62.1, «в телефоне все долги, а на
  ПК только новые»: ПК обновился с v0.42 сразу на v0.45+ и счёл `historyInvoices` своей старой таблицей — инвойсы до
  приложения так и не пришли): всё, что есть на сервере до курсора и чего здесь нет вовсе (и не удалено здесь — надгробие
  ждёт), кладётся как с сервера; своё не перезаписывается. Не убирать.
  Новый код пиши так, чтобы бизнес-правила оставались в `domain/` и `services/`, а UI не писал в таблицы в обход
  сервисов.
- PDF — `@react-pdf/renderer` (`app/src/pdf/documents.tsx`, оформление — `app/src/pdf/garage.tsx`): документы как у самой
  мастерской (её Tax Invoice и Quotation из Eaglecart) — английский + арабские подписи, шрифты Tinos (Times; латиница и
  кириллица) и Markazi Text (арабский). Арабский — отдельными блоками от английского и цифр (`BiLine`, `Ar`), иначе
  двунаправленный текст переставит номер; пробел в начале блока движок съедает — отступ или неразрывный пробел.
  Документы клиенту по умолчанию на английском (язык документов клиента/заказа — `en`).
  Инвойс, оплаченный целиком (`invoicePaidAt` в `domain/invoice.ts`: оплаты закрывают его или «Оплата у главного»), —
  со штампом PAID (`PaidStamp`, v0.38): рисуется при открытии (`invoicePdf`), сохранённый при выписке PDF не меняется.
  **Просмотр PDF — внутри приложения (v0.90**, владелец: «удобный просмотр PDF файлов внутри приложения»): `ui/PdfViewer.tsx`
  (`showPdf`, один `PdfViewerHost` в `App.tsx`): страницы рисует pdf.js на устройстве (`loadPdfjs` из `services/pdfText.ts`,
  холсты только у страниц рядом с экраном, не больше 10 Мп, перерисовка под масштаб после жеста), прокрутка — своя браузерная;
  два пальца и двойное касание — масштаб (на ПК Ctrl + колесо, + − 0, кнопки внизу); «Поделиться» (на iPhone — печать и «В
  Файлы») / «Сохранить», на ПК ещё «Открыть в браузере»; «Назад» и Escape закрывают только его. Сервисы открывают PDF через
  `openPdf` / `viewPdf` (`services/documents.ts`, просмотрщик ставит себя `setPdfViewer`; без него — как раньше: лист
  «Поделиться» или вкладка). PDF из чата WhatsApp и в «Проверить и отправить» — там же. Новое «открыть PDF» — только так.

## Структура `app/src`
- `domain/` — чистая логика без БД и UI: деньги, VAT, номера ОАЭ, телефоны, даты, позиции и согласования,
  этапы заказа, инвойсы, касса, отчёты, поиск по работам (`search.ts` — словарь RU/EN), дела «Сегодня» (`today.ts`),
  прибыль заказа (`profit.ts`), список поставщиков из Excel/CSV (`supplierSheet.ts`), книга поставщиков мастерской
  (`supplierBook.ts`), VIN (`vin.ts` — контрольная цифра, год, производитель, выбор из прочитанного; строка VIN по знакам — `vinRows.ts`, свой читатель знаков — `vinGlyphs.ts`, v0.35), долги (`debts.ts` —
  остаток заказа `orderDue`, карточки по клиенту `groupDebts`, раскладка оплаты `spread`/`allocate`, долг инвойсов до
  приложения `historyDues`, остаток кредита). Всё
  покрыто тестами.
- `db/` — схема Dexie и защита неизменяемых записей (хуки `guard`).
- `services/` — операции с данными (заказы, приёмка, оценка, запчасти, деньги, документы, сообщения, бэкап);
  удаление и правка любой операции денег — `entries.ts`, закрытие дня операции — `cashDays.ts` (v0.23); синхронизация
  с сервером мастерской — `sync/` (v0.40).
- `features/` — экраны по разделам; `ui/` — общие компоненты (`components.tsx`, `pwa.tsx` — установка и обновления,
  `device.ts` — хранилище и напоминание о копии, резервная копия — `services/backup.ts` (восстановление: каждый файл
  читается в память и хранится своей копией — кусок выбранного файла Safari на iPhone не хранит; окно —
  `features/settings/RestoreModal.tsx`), `ErrorBoundary`, `unsaved`, `backCloses`/`sheetSwipe` — жесты листов, `boardView.ts` — вид доски на устройстве;
  ПК (v0.41): `desk.tsx` — `useDeskShell`/`deskPage`, клавиши `useDeskHotkeys`/`DeskKeys`, меню правого клика
  `DeskMenu`, две колонки `DeskSplit`; `DataTable.tsx` — списки ПК таблицами; стили ПК — `src/desk.css`);
  `i18n/` — `ru.ts`, `en.ts`; `pdf/` — документы.
- `devtools/feedback/` — временный инструмент замечаний разработчика (v0.39, README там же): карандаш, режим выбора
  элемента, снимок с отметками, «Мои замечания», ZIP для агента. Изолирован: своя база `mygarage-feedback`, свои слова
  RU/EN (`strings.ts` — исключение из правила i18n, чтобы уходить целиком), свои классы `fb-` и `[data-fb-ui]`;
  в приложении — только `<FeedbackTool />` (`App.tsx`) и `<FeedbackSwitchRow />` (`ui/Appearance.tsx`). Бизнес-логику
  и данные приложения не трогает; новые сценарии e2e прячут карандаш (`mygarage.feedback = 0` в `addInitScript`).
  Лёгкий режим (v0.40.1 — на iPhone режим зависал): вход ничего не читает со страницы и не снимает, ничего не делает
  каждый кадр (рамка двигается от прокрутки и размера, мышь — не чаще кадра), без `backdrop-filter`; снимок — только по
  «Снимок» / «Весь экран», один за раз, с ограничениями `capture.ts` (только видимое, без ожидания картинок документа,
  ≤ 1,5 px на px и 2 Мп, в Safari ≤ 3 отрисовки, холсты и iframe библиотеки освобождаются сразу, неудача сама не
  повторяется) — автоснимок и покадровые циклы не возвращать.

## Жёсткие правила
- Деньги — целые филсы (`*Fils`), никаких float. VAT — базисные пункты (500 = 5 %). Считать только через
  `domain/money.ts`, `domain/vat.ts`, `domain/items.ts`, `domain/invoice.ts`, `domain/discount.ts`. Цена, набранная
  «VAT в цене», хранит брутто (`unitGrossFils`) — VAT выделяется из неё, итог строки не «уползает» на филс.
  Скидка — строки `kind: 'discount'` (`setDiscount`); после выписки — только кредит-нота + новый инвойс (`discountIssuedInvoice`).
  **Скидка строки (v0.82**, «скидки не общую, а в отдельности на каждую позицию»): `OrderItem.lineOff` — `{ pctBp }` или
  `{ grossFils }` (сумма с VAT); суммы строки — только `itemAmounts` (уже со скидкой; до неё — `amountsBeforeOff`, сколько —
  `itemOff`, цена за штуку — `unitGross`), в документах — её доля в колонке Discount (`discountFils` в `invoiceLines` и в
  снимке версии; `spreadDiscount` кладёт общую скидку поверх своей), в итогах — вместе с общей; у сказанной клиенту строки
  не меняется (`LOCKED_FIELDS`); выбор — `LineOffRow` (`features/job/LineOff.tsx`: 5 · 10 · 15 · 20 % · «Сумма») в «+ Цена» и
  листе строки, на строке заказа — «−10 %» зелёным, в сообщении клиенту — «(скидка 10%)».
  **Номера (v0.42.3, как в Eaglecart):** номер инвойса — номер работы: действующий «INV-2026-319» (`jobDocNumber`),
  отменённый кредит-нотой — «-1», «-2» (единственное, что меняется у инвойса, — номер), кредит-нота «CN-2026-319»;
  в PDF инвойса — только его номер (без «Order#» и «JOB ID»). Работы из Eaglecart — его номера (до 319; сделанная здесь
  Eaglecart-работа — `order.eaglecartNo`), свои — от 350 (`FIRST_OWN_NUMBER`); единственность номеров держит сервер
  (`server/src/numbers.mjs`, `push`), перенумерация — `store.renumber`. Двойная запись самого Eaglecart, убранная
  здесь, остаётся у оставшейся работы в `imported.twins` — перенос из Eaglecart её не вернёт.
  Строки после инвойса — `amendInvoice` (кредит-нота, заказ «в работе», «Готово» выписывает новый; `canAmendInvoice`:
  заказ открыт — и у машины, выданной в долг: v0.34, решение пользователя — она остаётся «Выдана», «Готово» выписывает
  новый инвойс (`quickInvoice` → `settleIfPaid`), долг — то, что он оставляет; расписка не меняется, строка «Долг до …»

## Команды (в `app/`)
- `npm install` — зависимости
- `npm run dev` — разработка (http://localhost:5173)
- `npm run typecheck` — TypeScript
- `npm test` — unit + сквозные тесты сервисов (fake-indexeddb)
- `npm run e2e` — браузерный сценарий целиком (нужен запущенный `npm run dev -- --port 5173`); скриншоты в `test-results/`.
  Браузер — Chromium из Playwright, если установлен (`npx playwright install chromium`), иначе Chrome или Edge с компьютера;
  выбрать явно — `E2E_BROWSER=chromium|chrome|msedge`
- `npm run e2e:motion` — стек телефона: переход, «Назад» с сохранённой прокруткой, свайп с экраном под пальцем,
  короткий свайп, вкладки, «Новый заказ» снизу, неподвижная панель, документ не прокручивается, нет переполнения вширь,
  во вкладке Safari край отдан свайпу Safari;
  `E2E_HAPTIC_LABELS=1 npm run e2e` — весь сценарий с метками отклика iPhone поверх кнопок (ничего не должно сломаться);
  `npm run e2e:photo` — чипы VIN, Mulkiya и механиков пальцем (касания как у телефона): тап — камера, удержание — только
  фото, ушедший палец и прокрутка — ничего, фото на своём месте после перезагрузки (тоже с `E2E_HAPTIC_LABELS=1`);
  `npm run e2e:whatsapp` — WhatsApp мастерской (v0.78) с сервером, сыгранным в странице (ни сервер, ни WhatsApp, ни чьи
  чаты не трогаются — все имена и сообщения придуманы): привязка кодом, чаты, переписка, отправка текста и файла,
  входящее, карточка чата, новый чат, «Чат» из заказа, смета с PDF из приложения; ПК — список и чат рядом; снимки —
  в `test-results/whatsapp/`;
  `npm run e2e:waauto` — WhatsApp сам (v0.79), сервер сыгран в странице: настройки (группы, босс, мойка выбраны среди
  чатов), согласование → рабочая группа и босс, строка «CAR WASH» → мойка, группа клиента в карточке и отчёт из заказа,
  поставщики выбраны и спрошены, ответ одного — цены вариантами на строках; снимки — `test-results/wa-auto/`;
  `node e2e/waload.cjs [300]` — поток событий WhatsApp (сервер с ~400 чатами сыгран в странице) при открытом заказе на
  телефоне и доске на ПК: время основного потока и долгие задачи (v0.80.2);
  `npm run shots` — скриншоты главных экранов телефона (светлая и тёмная тема) и ПК в `test-results/design/` для просмотра дизайна;
  с `SHOTS_SEED=1` id записей на странице повторяются от прогона к прогону (счётчик вместо `crypto.randomUUID`): два
  прогона, запущенные вместе (прежняя сборка и новая, каждая на своём порту), дают одинаковые кадры — сравнить телефон
  до и после правки ПК пиксель в пиксель;
  `node e2e/desk.cjs` — экраны ПК 1440×900 и 1920×1080, светлая и тёмная тема, в `test-results/desk/` (`SIZES=1440`,
  `SCHEMES=light` — часть);
  `npm run moves` — после `npm run build`: CPU переходов (заказ, лист, «Назад», вкладки, «Новый заказ») при замедлении ×4;
  сравнить две сборки — `node e2e/moves.cjs dist 4 <другая папка сборки>`; `HISTORY=1500 npm run moves` — то же с
  историей (запуск, архив, поиск, долги — то, что растёт с ней)
- `npm run build` — PWA для хостинга (`dist/`); `npm run preview` — открыть сборку на http://localhost:4173
- `npm run build:single` — один файл `dist-single/index.html` для превью
