# MyGarage — правила разработки

## Что это
PWA для менеджера небольшой автомастерской в ОАЭ (AED, VAT 5 %, интерфейс RU/EN).
Описание продукта — `docs/01`–`06`, текущее состояние — `docs/progress.md`.
Перед задачей читай связанный сценарий (`docs/02`), экран (`docs/03`) и данные (`docs/04`).

## Текущая архитектура (этап A — «на этом устройстве»)
- Всё приложение в `app/`: React 18 + TypeScript (strict) + Vite + Mantine 7 + React Router (HashRouter).
- Данные — IndexedDB через Dexie (`app/src/db/db.ts`), реактивное чтение — `useLiveQuery`.
- Облака пока нет: Supabase (`docs/05`) подключается следующим этапом. Новый код пиши так, чтобы
  бизнес-правила оставались в `domain/` и `services/`, а UI не обращался к таблицам в обход сервисов
  при записи — тогда замена хранилища не затронет экраны.
- PDF — `@react-pdf/renderer` (`app/src/pdf/documents.tsx`, оформление — `app/src/pdf/garage.tsx`): документы как у самой
  мастерской (её Tax Invoice и Quotation из Eaglecart) — английский + арабские подписи, шрифты Tinos (Times; латиница и
  кириллица) и Markazi Text (арабский). Арабский — отдельными блоками от английского и цифр (`BiLine`, `Ar`), иначе
  двунаправленный текст переставит номер; пробел в начале блока движок съедает — отступ или неразрывный пробел.
  Документы клиенту по умолчанию на английском (язык документов клиента/заказа — `en`).

## Структура `app/src`
- `domain/` — чистая логика без БД и UI: деньги, VAT, номера ОАЭ, телефоны, даты, позиции и согласования,
  этапы заказа, инвойсы, касса, отчёты, поиск по работам (`search.ts` — словарь RU/EN), дела «Сегодня» (`today.ts`),
  прибыль заказа (`profit.ts`), список поставщиков из Excel/CSV (`supplierSheet.ts`), книга поставщиков мастерской
  (`supplierBook.ts`), VIN (`vin.ts` — контрольная цифра, год, производитель, выбор из прочитанного), долги (`debts.ts` —
  остаток заказа `orderDue`, карточки по клиенту `groupDebts`, раскладка оплаты `allocate`, остаток кредита). Всё
  покрыто тестами.
- `db/` — схема Dexie и защита неизменяемых записей (хуки `guard`).
- `services/` — операции с данными (заказы, приёмка, оценка, запчасти, деньги, документы, сообщения, бэкап);
  удаление и правка любой операции денег — `entries.ts`, закрытие дня операции — `cashDays.ts` (v0.23).
- `features/` — экраны по разделам; `ui/` — общие компоненты (`components.tsx`, `pwa.tsx` — установка и обновления,
  `device.ts` — хранилище и напоминание о копии, резервная копия — `services/backup.ts` (восстановление: каждый файл
  читается в память и хранится своей копией — кусок выбранного файла Safari на iPhone не хранит; окно —
  `features/settings/RestoreModal.tsx`), `ErrorBoundary`, `unsaved`, `backCloses`/`sheetSwipe` — жесты листов, `boardView.ts` — вид доски на устройстве);
  `i18n/` — `ru.ts`, `en.ts`; `pdf/` — документы.

## Жёсткие правила
- Деньги — целые филсы (`*Fils`), никаких float. VAT — базисные пункты (500 = 5 %). Считать только через
  `domain/money.ts`, `domain/vat.ts`, `domain/items.ts`, `domain/invoice.ts`, `domain/discount.ts`. Цена, набранная
  «VAT в цене», хранит брутто (`unitGrossFils`) — VAT выделяется из неё, итог строки не «уползает» на филс.
  Скидка — строки `kind: 'discount'` (`setDiscount`); после выписки — только кредит-нота + новый инвойс (`discountIssuedInvoice`).
  Строки после инвойса — `amendInvoice` (кредит-нота, заказ «в работе», «Готово» выписывает новый; `canAmendInvoice`:
  машина в мастерской, долг не подписан); согласованная строка целиком — `reviseLine` (снова черновик).
  Названия работ и запчастей — заглавными (`lineName`, `itemTitle`; сохраняются так в `addItem`/`updateItem`, старые
  показываются так же; скидка — своими словами). Порядок строк — `position` (`byPosition`, `reorderLines`): смета,
  инвойс и PDF идут в нём.
  В документах скидка — не строкой с минусом, а долей в колонке Discount каждой строки и строкой в итогах (`spreadDiscount`);
  на экране — одной строкой, сколько бы ставок VAT ни было под ней.
  Отчёт (`domain/reports.ts`, экран и PDF владельцу) и прибыль заказа (`domain/profit.ts`) — **все суммы с VAT** (v0.22,
  решение пользователя): выручка — итоги инвойсов, запчасти — как куплены (`itemCostPaid`: закупка набирается без VAT,
  VAT продавца — записанный, иначе по ставке строки, **сразу в расходе** — v0.31, решение пользователя; «Куплено без VAT» —
  0), расходы — как в чеке; VAT отдельно не выделяется и не показывается. Расходы заказа в «Запчасти» (`code: 'parts'`) —
  это покупка его же запчастей: считается один раз — большее из закупки строк и этих расходов (`jobProfit` `partsCategoryId`,
  `partsPaid`; в отчёте — закупка строк сверх них). Выгрузка бухгалтеру (CSV) — по-прежнему с колонками без VAT / VAT / итог.
- Подписанные акты, отправленные версии оценки, решения клиента, инвойсы, долги (расписки) и журнал не изменяются и
  не удаляются — это обеспечивают хуки в `db/db.ts`. Исправление — только новой записью (дополнение к акту, новая
  версия, кредит-нота). Покупатель инвойса — его снимок `buyer`; что в нём пусто (клиента добавили после выписки),
  показывается и печатается из клиента заказа сейчас — только тот же человек, без TRN (`invoiceBuyer` в
  `domain/invoice.ts`: экран, PDF, CSV); PDF такого инвойса не хранится (`invoicePdf`), инвойс не меняется.
  **Деньги — любая операция удаляется и меняется (v0.23, решение пользователя: «все операции, какими бы они ни были,
  можно удалять, менять дату и т. д.»):** оплаты заказов, приходы (и «Оплата долга»), расходы (и «В кредит»), оплаты
  кредита, движения кассы, закрытия дня — без хуков в базе, только через `services/entries.ts`: `removeEntry` уводит
  операцию целиком (её движения кассы, фото, оплаты заказов из оплаты долга, оплаты кредита и зарплату расхода; движение
  операции — и пара «отменённая запись + обратное движение» до v0.23 — уводит саму операцию), «Отменить» —
  `restoreEntry`; `updateEntry` — день, сумма, способ, заметка, движение кассы идёт за операцией. Движение кассы
  принадлежит закрытию, которое посчитало день его операции (`services/cashDays.ts`, `closingFor`/`countedBy`, v0.23.1):
  набрана в свой день — первое закрытие после набора; набрана позже задним числом или перенесена на прошлый день —
  последнее закрытие того дня, иначе первое после него (время на часах при наборе не угадывается); перенесена на
  сегодня — ещё не посчитана. У оплаты заказа время набора — `typedAt` (у старых — `receivedAt`). Операция задним
  числом в посчитанный день (оплата заказа, расход, приход, оплата долга и кредита — `placeInDay`), перенесённая в
  него или снова ставшая наличной, идёт в закрытие того дня; цифры закрытия (и карта, перевод — оплаты, которые оно
  посчитало) всегда считаются из того, что в нём (`recountClosing`, и сразу при закрытии дня): пересчитанные наличные
  остаются, меняется расхождение — учёт и касса сходятся. Дата операции — не позже сегодня. Заказы идут за оплатами:
  снова должен — расписка открыта, закрытый — снова «Выдана» (долг на доске и в «Сегодня»); оплачен целиком — закрыт,
  как после оплаты; закрытый «Без оплаты» отпускает столько, сколько не оплачено сейчас; у работы на стороне «Оплачено» и
  цена — сколько сказал оплативший расход (цена после оплаты — в «Деньгах»). «Отменить» возвращает удалённое, только
  если есть то, на чём оно держится (оплата кредита — пока долг её принимает), поля — только если их с тех пор не меняли,
  открытое тогда движение — в закрытие, сделанное с тех пор (если было); закрытие — только после того же закрытия, что и
  раньше, и в тот же ряд; закрытия и долги считаются заново, а не возвращаются копией. Новое «Отменить» убирает прежнее
  (`undoToast`: отменить можно только последнее своё действие; итог, пришедший сам, — VIN с фото, — `replace: false`,
  ждёт своей очереди). Экраны не пишут эти таблицы сами. «Отменить запись» (`voidedAt` + обратное
  движение) больше не делается — `services/legacyVoid.ts` только для тестов старых данных.
  Пруфы — фото к любой записи денег, к приходу и к расходу (кроме закрытия дня), — в `media` со слотом `proof`
  (`services/proofs.ts`). Строка «Кассы» открывается листом своей записи учёта
  (`withEntries` в `domain/ledger.ts` → `EntryDetails`): оплата заказа, приход, расход или само движение (у отменённой
  до v0.23 — `entry.cancelled`: только «Удалить»). Лист операции: сумма — тап (`AmountEdit`), день — `DayPill`
  (`ui/DateFields.tsx`, не позже сегодня), способ — `PursePicker`, «Удалить» — с «Отменить». День оплаты выбирается и
  при оплате заказа (`addPayment` `date`), долга компании (`payCredit` `date`) и «Оплате долга» клиента.
  Удаление заказа целиком — только без документов и денег (`deleteJob` в `services/orders.ts`,
  проверка `domain/deletion.ts`, журнал снимает только `purgeJournal`), с «Отменить» сразу после.
- Позицию можно отметить выполненной только после согласия клиента (`canMarkDone`).
  Переходы этапов — только через `changeStage` (правила в `domain/stages.ts`); закрытый/отменённый заказ возвращается
  только `reopenJob` (`canReopen` / `reopenStage`).
- Главный путь — ленивый (v0.5), для менеджера с двумя механиками: принял → что нашли → запчасти → цена клиенту →
  согласие → работа → оплата → выдал. Машина принимается по одному номеру (`checkIn`, одна кнопка «Принять») и сразу
  открывается **экран заказа** `features/job/JobPage.tsx` (`/orders/:id`): строки, одна главная кнопка по шагу, всё
  редкое — плитки под «…». Шаг заказа (`Phase`: look · price · wait · work · pay · out · debt) читается из фактов
  (`domain/flow.ts`, `phaseOf` в `services/flow.ts`), этап двигается сам (`syncStage`) — **не добавлять ручных
  переключений этапа в главный путь**. Двигает его действие, не просмотр: открытие заказа ничего не пишет (доска
  ставит изменённый заказ первым); машина на месте создаётся сразу на «Диагностике» (`createOrder`: «Принять», гарантия),
  запись — «Приехал» (`carArrived`); отзыв строки, ждущей ответа, — `takeBack`, «сделано» — `lineDone`, одна строка прочь —
  `removeLines`. Ответ клиента — `approveAll` / `answerLines` / `refuseAll` / `dropLine`
  (версии и решения пишутся как в подробном пути); новая цена сказанной строки — тап по сумме в её листе, `repriceLine`
  (ждёт ответа → черновик с новой ценой; согласована → версия `price_change` только с ней, согласовано лично; до инвойса);
  «Готово» — `quickInvoice` (согласует оставшееся лично, отмечает
  выполненным, выписывает инвойс, заказ → «Готово»); после оплаты — «Выдать» (`closed` из любого рабочего этапа, если
  инвойс оплачен или подписан долг, либо платить не за что). В листе оплаты (`PaymentModal`, v0.19) рядом со способами
  оплаты — «В долг» (`canLeaveOnDebt`): сумма, срок и подпись клиента прямо в листе — машина выдана (`leaveOnDebt`:
  этап «Выдана», шаг «долг»; заказ — в «Деньги → Долги», под «Итого» — строка «Долг до …» с распиской; оплата, которая
  гасит долг, закрывает заказ) — и «Без оплаты»: закрыть без оплаты и без долга (`closeUnpaid`: отметка `order.waived`,
  долг списан, инвойс и оплаты как были); в «…» их нет;
  «Оплата у главного» — `closeUnpaid(id, 'owner')` (`waived.via`): клиент заплатил владельцу, в кассу менеджера
  ничего, выручка остаётся.
  **Долги (v0.20, `services/debts.ts`, экраны — `features/money/Debts.tsx`):** долг клиента — заказ «Выдана»/«Закрыт» с
  остатком > 0 (`orderDue`; `bundleAmountDue` — она же); одна карточка на клиента (`DebtorList`) — на доске вкладкой
  «Долги» рядом с «Архивом» и в «Деньги → Долги»; такие заказы не в общем списке доски (шага `debt` в её фильтрах нет) и
  не в архиве, пока не оплачены. «Оплата долга» — один приход (`incomes.category = 'debt'`, `addDebtPayment`): одно
  движение денег, разложено по заказам клиента оплатами с `payment.incomeId` (сначала выбранный, потом самый старый),
  лишнее — приход без долга; в учёте строка — приход, не оплаты. Расход «В кредит» (`expense.method = 'credit'`) — без
  движения денег и без строки учёта; оплаты — `creditPayments` (`payCredit`, частями; наличные — из кассы, строка
  «Оплата кредита»); «Долги компании» — расходы в кредит с остатком.
  **Категории прихода (v0.26)** — таблица `incomeCategories`, как у расходов (`services/incomeCategories.ts`,
  `domain/incomeCategories.ts`): «Работа / ремонт», «Продажа», «Прочий приход», «Emil» и свои (`c_…`); приход хранит
  код. Чипы — только `IncomeChips` (`features/money/MoneyEntry.tsx`): «＋» — новая и сразу выбрана, удержание — название
  и «Удалить» с «Отменить» (`active = false`, не удалять строку: у записей название остаётся); подпись записи —
  `useIncomeLabel`, не `income.category.*` напрямую. «Прочий приход» не убирается; `debt` — не категория, её не трогать.
  Экрана акта приёмки (фото по кругу, отчёт приёмки с подписью — бывший «…» → «Фото») нет с v0.21: осмотр — Job card;
  акты, снятые раньше, хранятся и показываются как прежде (гарантийная страница, PDF акта, фото машины и Mulkiya из
  акта, поиск) — данные и `services/inspections.ts` не удалять; старый адрес `/orders/:id/intake` открывает заказ.
  Акта выдачи нет. В «…» нет «Фото», «Механику» и «Скидка» (v0.21): механики — чипами на карточке (удержание чипа, на
  ПК — правый клик, — задание механикам, `MechanicSheet`), скидка — «％» под строками, и под выписанным инвойсом, пока
  его можно изменить и есть что платить (кредит-нота + новый инвойс). Подробного пути («Подробно»:
  вкладки, подробная смета A/B/C, «Нашли ещё», акт выдачи, журнал, ручная смена этапа) нет с v0.15 — не возвращать
  его экраны: всё — главным путём.
- Дела по всем машинам — только из фактов заказа (`domain/today.ts` → «Сегодня» на доске — колокольчик `TodayBell` в
  шапке, v0.30): новое «что сделать» — новый вид задачи там, не отдельный блок или подсказка. Карточка доски (v0.30):
  строка «что за работа» — `jobSummary`, кнопка «Смета»/«Инвойс» — `.job-card-doc`, свайп вправо — WhatsApp клиента
  (`useSwipeRow` leading). Свайп между вкладками панели — `ui/mainSwipe.ts` (переходы стека `slide-next`/`slide-prev`);
  страницы внутри вкладки — `useTabSwipe` с `onEdge`, вложенные — `data-own-swipe`. Долги — вкладки-суммы, свёрнутые
  клиенты, выписка `statementPdf` (`pdf/statement.tsx`) и ZIP инвойсов `debtInvoicesZip` (`services/debtDocs.ts`). Заказ в группу мастерской — «Поделиться» в шапке заказа (`ShareJobButton`, текст `jobShareText`: имя
  клиента без телефона, жалоба клиента, если записана). Механиков на заказе может быть несколько (`order.mechanicIds`,
  читать через `mechanicsOf` в `domain/crew.ts`; `toggleMechanic`, `mechanicId` — первый из них). Срок готовности —
  «…» → «Срок» (`DueSheet`); чип срока на карточке — только когда срок назначен. **Job card** — чип после Mulkiya
  (`features/job/JobCard.tsx`): машина в 3D (v0.19, `ui/Car3D.tsx` → `ui/car3d/scene.ts`: three.js только в этом
  куске сборки, седан из своих сечений, без файла модели; кадры — только пока что-то движется; без WebGL — 2D-схемы),
  палец поворачивает, «3D · Сверху · Слева · Справа · Спереди · Сзади» — к стороне; два пальца (на ПК колесо) — ближе к
  месту между ними и сдвиг (v0.20), вблизи — «Вся машина»; точку ставит только короткое неподвижное касание стоящей машины
  (щипок, поворот, касание, которым ловят докат, — нет); детали кузова (швы, ручки, пороги, кромки арок, стойки, фары,
  зеркала) лежат на нём по его рёбрам (`Faceted`, `refine`/`spans`) — сам кузов не менять, иначе сдвинутся сохранённые
  точки; лист Job card не меняет высоту (`.jc-sheet`); тап — точка повреждения (тип чипами,
  фото — камера, удержание — из телефона); точки — это отметки повреждений акта приёмки (`damageMarks`; акт создаётся
  на первой точке, подписанный — только просмотр), хранятся как прежде — сторона и место на её 2D-схеме
  (`domain/damage3d.ts`: сторона — по направлению поверхности, у машины носом к +z её левая сторона — +x; старая точка
  находится на 3D лучом снаружи), поэтому акт и PDF не меняются. **VIN и год с фото** (v0.18) — снятое фото VIN или Mulkiya читается само на устройстве

## Команды (в `app/`)
- `npm install` — зависимости
- `npm run dev` — разработка (http://localhost:5173)
- `npm run typecheck` — TypeScript
- `npm test` — unit + сквозные тесты сервисов (fake-indexeddb)
- `npm run e2e` — браузерный сценарий целиком (нужен запущенный `npm run dev -- --port 5173`); скриншоты в `test-results/`.
  Браузер — Chromium из Playwright, если установлен (`npx playwright install chromium`), иначе Chrome или Edge с компьютера;
  выбрать явно — `E2E_BROWSER=chromium|chrome|msedge`
- `npm run e2e:motion` — стек телефона: переход, «Назад» с сохранённой прокруткой, свайп с экраном под пальцем,
  короткий свайп, вкладки, «Новый заказ» снизу, неподвижная панель, документ не прокручивается, нет переполнения вширь,
  во вкладке Safari край отдан свайпу Safari;
  `E2E_HAPTIC_LABELS=1 npm run e2e` — весь сценарий с метками отклика iPhone поверх кнопок (ничего не должно сломаться);
  `npm run e2e:photo` — чипы VIN, Mulkiya и механиков пальцем (касания как у телефона): тап — камера, удержание — только
  фото, ушедший палец и прокрутка — ничего, фото на своём месте после перезагрузки (тоже с `E2E_HAPTIC_LABELS=1`);
  `npm run shots` — скриншоты главных экранов телефона (светлая и тёмная тема) и ПК в `test-results/design/` для просмотра дизайна;
  `npm run moves` — после `npm run build`: CPU переходов (заказ, лист, «Назад», вкладки, «Новый заказ») при замедлении ×4;
  сравнить две сборки — `node e2e/moves.cjs dist 4 <другая папка сборки>`
- `npm run build` — PWA для хостинга (`dist/`); `npm run preview` — открыть сборку на http://localhost:4173
- `npm run build:single` — один файл `dist-single/index.html` для превью
