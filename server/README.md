# MyGarage — сервер мастерской

Свой сервер на компьютере мастерской: все данные приложения и все файлы лежат в одной папке на этом ПК, а телефоны и
другие устройства синхронизируются с ним. Бесплатно: Node.js и Tailscale (бесплатный план).

## Что где лежит — `C:\MyGarage`

| Папка | Что в ней |
|---|---|
| `Служебное\garage.db` | все записи приложения (заказы, клиенты, деньги, инвойсы, журнал) — база SQLite |
| `Фото и видео\ГГГГ-ММ\` | фото машин и запчастей, видео, голосовые, подписи — оригиналы |
| `Документы\Инвойсы\ГГГГ-ММ\` | PDF, как их сделало приложение: инвойсы, а рядом `Сметы`, `Акты`, `Чеки`, `Долги` |
| `Резервные копии\` | копия базы каждый день (последние 30) |
| `Служебное\Превью`, `Служебное\Файлы` | маленькие превью и рабочие копии PDF — не трогать |
| `Служебное\server.log` | журнал сервера |

Копия всей мастерской — копия этой папки целиком.

## Как сервер работает сейчас (Windows, без Docker)

Сервер запускается сам при входе в Windows (ярлык `MyGarage Server.vbs` в автозагрузке) и работает без окна.

- Страница сервера на этом ПК: **http://localhost:8788** — адрес для телефона, код подключения (15 минут), устройства
  (любое можно отключить), папка данных.
- Поставить автозапуск и запустить: `powershell -ExecutionPolicy Bypass -File server\windows\install-autostart.ps1`
- Убрать автозапуск и остановить: `powershell -ExecutionPolicy Bypass -File server\windows\uninstall-autostart.ps1`
- Сервер сторожит сам запуск (v0.42.1): остановился по любой причине — через 2 секунды он снова работает; ошибки
  пишутся в `Служебное\server.log`.
- Номера (v0.42.3): номер инвойса — номер работы (INV-2026-319), свои заказы — от 350; сервер следит, чтобы у двух
  заказов не было одного номера (`src/numbers.mjs`). Перенумеровать всё на этом ПК: `POST http://localhost:8788/renumber`
  с `{"fixed": {"<id заказа>": <номер Eaglecart>}}` — покажет план; с `"apply": true` — сделает.
  Каждому устройству сервер держит по три номера (v0.84.2, `POST /api/sync/numbers`). Заказ, сделанный без связи, берёт номер
  из них перед инвойсом, поэтому два устройства без туннеля не выпишут один номер. Счётчик стоит после них.
- Приложение на этом же ПК берёт фото и видео с сервера напрямую (`http://127.0.0.1:8787`), не через туннель.
- Новый адрес устройства находят сами (v0.42.2): адрес туннеля меняется после перезагрузки ПК, поэтому сервер оставляет
  его на ntfy.sh (бесплатно, без регистрации) для каждого подключённого устройства — зашифрованным ключом, который есть
  только у этого устройства, под ничего не значащим именем (`src/relay.mjs`). Устройство, не достучавшись до сервера,
  забирает адрес оттуда и проверяет свой ключ на новом адресе. Выключить: переменная `RELAY_URL` пустая.
- Перезапустить (после обновления): `powershell -ExecutionPolicy Bypass -File server\windows\restart.ps1` — туннель
  Cloudflare работает отдельно от сервера, поэтому адрес у телефонов остаётся тот же (меняется только после
  перезагрузки ПК). Туннель всегда один (v0.62.3): запускаясь, сервер оставляет свой туннель и останавливает все прочие
  cloudflared из своей папки.
- Уведомления на телефоны (v0.74, `src/push.mjs`): приложение оставляет серверу план — о чём и когда напомнить, — а
  сервер сам шлёт уведомления через сервисы пушей Apple и Google (Web Push; сообщение зашифровано для телефона, ключи
  сервер делает сам и хранит в базе). Телефону для этого не нужно достучаться до сервера — нужен только интернет на ПК.
  Включить: в приложении «Ещё → Уведомления». На странице сервера — блок «Уведомления»: сколько устройств их
  принимает, что в плане, когда ушло последнее. Кто отправитель (поле `sub` для сервисов пушей) — адрес приложения;
  другой — переменная `PUSH_CONTACT` (`mailto:…` или `https://…`).
- WhatsApp мастерской (v0.78, `whatsapp\bridge.mjs`, `src\whatsapp.mjs`): этот ПК — одно связанное устройство WhatsApp
  мастерской (как WhatsApp Web), и приложение показывает чаты и отправляет сообщения и файлы через сервер. Работает в
  Chrome этого компьютера без окна; отдельным процессом рядом с сервером, со своими пакетами — сам сервер остаётся без
  зависимостей и запускает его сам. Установить один раз: в папке `server\whatsapp` выполнить
  `set PUPPETEER_SKIP_DOWNLOAD=true` и `npm install` (браузер не скачивается — берётся установленный Chrome или Edge;
  после установки сам накладывается патч из `whatsapp\patches`), затем перезапустить сервер (`windows\restart.ps1`).
  Привязать: на странице сервера блок «WhatsApp» → «Привязать WhatsApp» → отсканировать QR телефоном (WhatsApp →
  Настройки → Связанные устройства → Привязка устройства); или из приложения: «Ещё → WhatsApp → Настройка» — там же код
  для ввода в телефоне вместо QR. Отвязать — там же или в телефоне. Что хранится здесь:
  `C:\MyGarage\Служебное\whatsapp` — сессия (это весь аккаунт: папку никому не отдавать), файлы, которые открывали в
  приложении (30 дней), и картинки контактов. Переписка не копируется — читается из WhatsApp по запросу. Мост слушает
  только этот компьютер (127.0.0.1:8790) и отвечает только серверу; приложение обращается к серверу по ключу устройства,
  как за всем остальным. Это неофициальный клиент WhatsApp: сервер пишет только то, что отправил человек в приложении,
  и не больше 25 сообщений в минуту — рассылок нет и быть не должно (за них WhatsApp блокирует номер). После обновления
  WhatsApp Web мост может перестать входить, пока библиотека не обновится: связанная сессия при этом работает, новая
  привязка — нет; обновить — `npm install whatsapp-web.js@latest` в `server\whatsapp`. В Docker моста нет (нужен Chrome).
- WhatsApp сам (v0.79, `src\waOutbox.mjs`): отчёты в рабочую группу и группы клиентов, сообщения боссу (сметы, инвойсы,
  оплаты, приходы, расходы), мойка, заявки поставщикам — приложение отдаёт их серверу, и сервер шлёт сам, когда WhatsApp на
  связи: по одному, с паузами, одно и то же — один раз. Очередь — файлы в `C:\MyGarage\Служебное\whatsapp\outbox`
  (`sent.json` — что ушло); на странице сервера в блоке «WhatsApp» — «Отправляется само»: в очереди, не ушло, ушло. Что и
  куда — в приложении: WhatsApp → Настройка → Автоматизация.
- Проверка: `server\test` — `npm test` в папке `server`.

Компьютер не должен засыпать, пока мастерская работает: Параметры → Система → Питание → «Спящий режим: Никогда».
Пока ПК выключен, телефон работает как раньше, а синхронизируется, когда сервер снова на связи.

## Доступ из любой сети — Tailscale Funnel (бесплатно)

Приложение открывается с `https://neyron357-boop.github.io`, поэтому серверу нужен постоянный HTTPS-адрес, видимый из
интернета. Tailscale Funnel даёт его бесплатно, без белого IP и без настройки роутера; на телефон ничего ставить не нужно.

1. Установить Tailscale на этот ПК (tailscale.com/download или `winget install -e --id Tailscale.Tailscale`) и войти
   (Google, Apple, Microsoft или GitHub).
2. В командной строке: `tailscale funnel --bg 8787`. В первый раз Tailscale покажет ссылку — открыть её и разрешить
   HTTPS и Funnel для этого ПК (один раз).
3. Адрес вида `https://desktop-81a9b11.<ваша-сеть>.ts.net` появится на странице сервера (http://localhost:8788).

## Подключить телефон

1. На ПК открыть http://localhost:8788 — там адрес и код (6 цифр, действует 15 минут; «Новый код» — ещё один).
2. На телефоне: **Ещё → Настройки → Данные → Сервер мастерской** → адрес и код → «Подключить». Можно нажать «Скопировать
   ссылку для телефона» на ПК, отправить её себе и вставить в поле адреса — код подставится сам.
3. **Главный — телефон** (v0.41.1): iPhone с данными делает их данными мастерской — всё, чего у него нет, уходит с
   сервера и с других устройств; на телефон при этом ничего не приходит. Компьютер с данными, когда на сервере уже есть
   данные, только берёт их (его прежние заменяются — приложение спросит). До выбора ничего не синхронизируется. Главное
   устройство на странице сервера отмечено «· главное»; отключите его там — главным может стать новый телефон.

Дальше всё само: изменения уходят через несколько секунд, приходят при открытии приложения и раз в минуту. Фото и PDF,
когда они уже на сервере, уходят с телефона («Освобождать память»): остаются маленькие превью, оригинал открывается с
сервера.

## Перейти на Docker

Docker Desktop на этом ПК не запустится, пока в BIOS выключена виртуализация (сейчас: «Virtualization Enabled In
Firmware: No»; процессор i5-6500 её поддерживает).

1. Включить виртуализацию: перезагрузить ПК, при включении нажимать **F10** (HP), раздел **Advanced → System Options**
   или **Security → System Security** → **Virtualization Technology (VTx)** → Enabled → сохранить (F10).
2. Установить Docker Desktop (бесплатно для небольшого бизнеса): `winget install -e --id Docker.DockerDesktop`.
3. Остановить сервер Windows: `powershell -ExecutionPolicy Bypass -File server\windows\uninstall-autostart.ps1`
   (и `tailscale funnel --bg off`, если Funnel включали на самом ПК).
4. В папке `server`: `docker compose up -d --build`, затем `docker compose logs tailscale` — открыть ссылку входа в
   Tailscale. Данные остаются в той же `C:\MyGarage`; Docker запускает контейнеры сам после перезагрузки.

Адрес в Docker будет `https://mygarage.<ваша-сеть>.ts.net` — его нужно один раз ввести в приложении заново
(Сервер → Отключить → Подключить с новым адресом и кодом); данные на сервере те же.

## Как устроено

- `src/main.mjs` — запуск; `src/store.mjs` — база и файлы; `src/api.mjs` — API приложения; `src/admin.mjs` — страница
  на ПК. Без внешних зависимостей: Node 22+ (встроенная SQLite).
- Каждая запись хранится как есть (JSON) с номером изменения; устройство берёт изменения после последнего виденного
  номера. Моментально (v0.41.2): каждое устройство держит поток `/api/sync/events` (`src/events.mjs`) — сервер сразу
  говорит, что другое устройство что-то изменило, и оно забирает это (≈0,2 с); на странице сервера — «● на связи сейчас».
- Фото (v0.41.3): рядом с оригиналом — превью и карточка 1080 px (`Служебное\Превью\<id>.card.jpg`); карточки старых фото
  этот ПК делает сам средствами Windows (`src/cards.mjs`). Файлы отдаются частями (видео играет по мере прихода) и по
  адресу с ключом только для файлов — так их грузят элементы картинок и видео. Побеждает последняя запись; номера заказов и инвойсов (`counters`) только растут.
- Удалённое на телефоне фото на сервере не стирается (его можно вернуть «Отменить»).
- ИИ мастерской (v0.48, `src/ai.mjs`): Gemini с ключом, который хранится только на этом ПК — `Служебноеai.json` (вводится на
  странице сервера, «ИИ (Gemini)»; или переменная `GEMINI_API_KEY`). Устройства спрашивают `/api/ai/vin` (VIN → машина:
  факты расшифровщика NHTSA vpic.nhtsa.dot.gov и Gemini) и `/api/ai/part-name` (название запчасти без опечаток и
  по-английски). До 120 вопросов в минуту с устройства. v0.49: ответы хранятся в базе (`ai_cache`: VIN, название и чек —
  год), размышления — `low` (короткие вопросы лёгким моделям — минимальные); что потрачено (вопросы, токены) —
  `Служебное\ai-usage.json` и на странице сервера.
  v0.85 (решение владельца: «Убери поиск каталогов полностью, направим ИИ на более нужные и с меньшим расходом. Оставь
  определения VIN.»): поиска номера детали, её схемы и фото в каталогах (`/api/ai/part-find`, `/api/ai/progress`,
  `src/partfind.mjs`, `src/catalog.mjs`, поиск Google в Gemini) больше нет — за неделю на него уходило ~80 % вопросов, все
  платные поиски Google и большая часть токенов размышлений. Не возвращать без решения владельца.
  v0.50: `/api/ai/receipt` (фото чека поставщика, тело до 8 МБ) — лёгкая модель читает продавца (имя, TRN, телефон, адрес),
  вид бумаги (запчасти · подрядчик · топливо · еда · прочее), строки, суммы и VAT; ответ хранится по хэшу картинки (год).
  v0.50.2: чек читает сильная модель первой (дата как напечатана — `dateText`, скрытая цифра — `dateSure`; у строки —
  `part` и `car`); к какому заказу чек — решает только приложение.
- Безопасность: устройство получает свой ключ только по коду с этого ПК; ключ можно отозвать на странице сервера;
  вызывать API со страниц может только адрес приложения (CORS); страница сервера доступна только на этом ПК.
